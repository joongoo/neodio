# 00. SYNTHESIS — 6개 오픈소스 조사 통합 정리

대상(분석 순서): ① geo-aeo-tracker ② ai-visibility-tracker ③ geo-visibility-lab ④ langfuse ⑤ openlit ⑥ phoenix
각 프로젝트 문서: `01-geo-aeo-tracker/` … `06-phoenix/` (각 7종: 01 개요, 02 아키텍처, 03 로직, 04 아이디어, 05 독립 설계, 06 IP, 07 도입 판단)

## 1. 가장 중요한 결론 (먼저 읽기)

1. **제품 구조(멀티테넌트, 점수, 수집, 버전 체계)는 Neodio가 6개 모두보다 앞서 있다.** 가져올 것은 새 화면이 아니라 **측정의 엄밀함 · 운영 스케일의 기반 · 의미 판정의 검증 체계**다.
2. **Neodio가 지금 비어 있는 두 곳을 6개가 정확히 채워준다**: (a) 감성/추천 판정이 신뢰 불가라 점수에서 제외된 상태 → 판정기(D4), (b) 수집 잡이 프로세스 메모리 → 내구성 있는 잡 엔진(D5).
3. **판정기는 골드셋 체계(D13) 없이는 지표에 넣으면 안 된다.** 6개 프로젝트 중 어디도 이 검증을 제대로 하지 않는다. 이것이 정확도 우선 원칙을 실행하는 수단이자 Neodio의 차별점이 될 수 있다.
4. **IP 위험은 프로젝트마다 크게 다르다**(§3). 코드 이식은 6개 모두 금지. 특히 ② AGPL, ⑥ ELv2+특허는 취급을 달리해야 한다.
5. **LLMO 비교 논의에서 나왔던 에이전틱 트래픽(CDN 로그), 엣지 배포, 네이버 AI 검색은 6개 중 어느 것도 다루지 않는다.** 그 영역은 이번 조사로 얻은 것이 없다(별도 설계 필요). → 에이전틱 트래픽은 별도 조사함: [../agentic-traffic-research.md](../agentic-traffic-research.md) (D14). 엣지 배포와 네이버 AI 검색은 아직 비어 있음.

## 3. 프로젝트별 IP 취급

| # | 프로젝트 | 라이선스 | 취급 |
|---|---|---|---|
| ① | geo-aeo-tracker | MIT | 아이디어만 사용. Rank Signal은 제3자(DEJAN) 방법론 파생이라 D3 구현 전 확인 |
| ② | ai-visibility-tracker | **AGPL-3.0** | 아이디어만. 채점 프롬프트 원문을 읽었으므로 **구현은 05만 읽는 새 세션** |

| ⑤ | openlit | Apache-2.0 (CE) | 엔터프라이즈 영역은 이 트리에 없음. 가드 오류 정책은 의도적으로 반대로 설계 |
| ⑥ | phoenix | **ELv2 + 특허 고지** | 구현 비열람, 일반 방법론만. **D13 도구화 전 변리사 검토 필수** |

## 4. 권장 순서

**0단계 — 코드 변경 없는 점검 (바로 가능, 효과 큼)** — a~d 결과: [00a_BASELINE_CHECKS.md](00a_BASELINE_CHECKS.md)

| # | 점검 | 목적 |
|---|---|---|
| a | 짧은 라틴 별칭이 있는 실제 브랜드의 기존 응답 샘플 점검 | D7 필요성·규모 확인 (현재 매칭에 단어 경계 검사가 코드상 없음) |
| b | 프롬프트 편집 전후 주간 지표가 이어지는 방식 확인 | D9 필요성 확인 |
| c | 서버가 외부 URL을 가져오는 모든 지점과 방어 수준 목록 | D10 범위 확인 (연결 시점 IP 검증 여부 미확인) |
| d | 외부 텍스트가 LLM 프롬프트로 들어가는 모든 기능과 방어 수준 목록 | D12 범위 확인 (콘텐츠 수정 가이드가 페이지 본문을 프롬프트에 붙임) |
| e | **골드셋 파일럿**: `prompt_runs`에서 층화 200건을 두 명이 스프레드시트로 라벨링해 일치도 측정 — **라벨링 종료, 골드 v0 생성**(규칙 기반 언급 정확도 98.0%; 순위·입장 검증은 한계 있음) ([00b_GOLD_PILOT_PREP.md](00b_GOLD_PILOT_PREP.md)) | 판정 정의가 모호한지 먼저 확인 (코드·특허 무관, 즉시 가능) |

## 5. 각 프로젝트가 기여한 핵심 한 줄

① 표본 크기를 반영한 변화 판단과 비용 통제 · ② LLM 구조화 평가와 내구성 있는 잡 · ③ 정확한 매칭 경계와 "비교 가능성" 규율 · ④ 평가 거버넌스·단가 이력·연결 시점 IP 검증 · ⑤ 신뢰할 수 없는 텍스트 방어 · ⑥ 골드셋 → 보정 → 게이트 절차

## 6. 모든 프로젝트에서 검증하지 못한 것 (종합)

- 어느 저장소도 **테스트를 실행하지 않았다.** 한국어 입력 동작은 전부 미검증.
- 의존성 라이선스 전수, 각 서비스 약관(Bright Data, DataForSEO, Tencent WSA 등) 미검증.
- Neodio 쪽 현황: 매칭 오탐 실제 비율, 추세와 편집의 상호작용, 외부 URL/텍스트 경로 방어, `prompt_runs` 재현성 필드 — 모두 0단계 점검 대상.
- ④ web 계층·대시보드, ⑤ 가격 JSON 전체·컨트롤러, ⑥ 서버 구현은 정독하지 않음(⑥은 의도적).
