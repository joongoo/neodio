# 04. IDEA_EXTRACTION — geo-aeo-tracker → Neodio

원칙: 구현이 아니라 **문제 → 입력 → 출력 → 한계 → 일반 원리 → Neodio 대안** 순으로 추상화한다. Neodio 현황은 이 저장소를 직접 읽고 확인한 것만 적는다.

## 0. 먼저: Neodio가 이미 앞선 영역 (가져올 것 없음)

| 영역 | 원본 | Neodio (확인 근거) |
|---|---|---|
| 멀티테넌트·권한 | 없음(공유 비밀 1개) | 조직·멤버십·브랜드별 권한 (`neodio_memberships`, `neodio_membership_brands`) |
| 저장·재현성 | 상태 JSON 덮어쓰기 | `prompt_runs`/`run_analyses`/`brand_observations`/`citations`, `config_versions`, `change_log` |
| 점수 설계 | 가산식 루브릭 | 가중 3요소 + 위치 중요도 + 반복 실행 가중 + 감성 제외 (`processing/visibility.ts`) |
| 수집 | 제3자 스크래퍼 위탁 | 공식 API + 자체 Playwright(네이버·구글) |
| 언어 | 영어 감성 목록 | 한국어 조사 처리 포함 매칭 (`processing/text.ts`) |

→ 원본에서 얻을 가치는 **아래 5가지 아이디어**에 한정된다.

## I1. 통제된 쌍대 실험으로 "무엇이 선택되게 하는가" 검증

1. 사용자 문제: "콘텐츠를 이렇게 고치면 AI가 더 잘 인용할까?"를 상관이 아닌 인과에 가깝게 검증하고 싶다.
2. 입력: 질의, 문단(자사/경쟁), 검증할 텍스트 특징
3. 출력: 특징별 승률과 불확실성 구간, 판정(효과 있음/없음/불충분)
4. 요구사항: 특징 외 다른 요소 통제, 편집 자체 효과 분리, 재현 가능, 비용 상한
5. 원본의 한계: 판정자는 실제 AI 검색이 아닌 대리 모델, 표본 작음, 다중 비교 보정 없음, 단일 모델
6. 일반 원리: 짝지은 실험 설계, 위약 대조, 순차 검정, 베이지안/빈도주의 구간 추정
7. Neodio 대안: 판정 모델 다중화(최소 2개 + 불일치율 보고), **실제 수집 데이터로 교차 검증**(판정 선호가 우리 `citations` 실측과 일치하는지 보정), 다중 비교 보정, 한국어 문단 지원
8. 개선: 실험 결과를 "추천"이 아니라 **기회 카드의 근거 강도**로 연결
9. 검증: 알려진 효과(예: 질의 키워드 포함)와 알려진 무효과(위약)에 대해 방법이 양/음을 올바르게 재현하는지 보정 실험

## I2. 호출 전 비용 추정 + 전역 예산 통제

1. 문제: 대량 배치·AI 생성 기능의 비용 폭주
2. 입력: 모델별 단가, 예상 토큰, 조직 한도
3. 출력: 실행 전 예상 비용, 초과 시 거부/축소, 실행 후 실비 기록
4. 요구: 조직별·기간별 한도, 인스턴스 간 공유
5. 한계(원본): 지출 원장이 메모리라 인스턴스 간 공유 안 됨 — 자체 주석이 인정
6. 원리: 토큰 버킷/원장, 사전 예약-사후 정산
7. Neodio 대안: DB 기반 원장(조직·일 단위) + 기존 `rateLimit.ts`(메모리, 분당 호출) 대체/보완. Neodio 현재는 **분당 호출 수만** 제한하고 비용 단위 통제는 없음(문서 `llm-collection.md` 기준)
8. 개선: 원본보다 한 단계 더 — 전역 공유
9. 검증: 동시 실행 N개에서 한도 초과 0건인지 부하 테스트

## I3. 표본 크기를 반영한 변화 감지(드리프트)

1. 문제: 주간 점수 변화가 진짜 변화인지 노이즈인지 구분
2. 입력: 기간별 (언급 실행 수, 전체 실행 수)
3. 출력: "유의한 변화" 플래그와 구간
4. 원본 한계: 고정 임계값 → 표본 수 무시
5. 원리: 비율 차이의 신뢰구간/검정, 소표본 보정
6. Neodio 대안: 이미 주간 `visibility_scores`와 반복 실행 가중이 있으므로 **같은 가중 표본 크기로 구간을 계산**해 변화 카드에 "노이즈 가능" 표시. 문서 `help.ts`의 "답변 변동성은 정상" 안내를 수치로 뒷받침
7. 검증: 과거 데이터 재생(백테스트)으로 거짓 알림 비율 측정

## I4. AEO 사이트 진단 항목 보강

1. 문제: 자사 사이트가 AI에 읽히는가
2. 요구: AI 크롤러별 접근 허용 여부, 규격에 맞는 robots 해석
3. 원본 특징: 크롤러별 허용 판정에서 4xx는 제한 없음, 5xx·오류는 보수 처리(RFC 9309)
4. Neodio 현황: `robotsTxtReader.ts` 존재, 구조화 데이터·콘텐츠 가시성 회복 기회 존재. **크롤러별 판정 규칙이 RFC 9309와 일치하는지는 미확인** → RESEARCH
5. 주의: llms.txt 효과는 입증되지 않음 → 점수화하지 말고 "참고" 등급

## I5. 서버 요청 URL 방어(SSRF) 점검 목록

1. 문제: 사용자 입력 URL을 서버가 가져올 때의 내부망 노출
2. Neodio 현황: `pageText.ts`에 "IP·localhost 거부, 리다이렉트마다 재검사" (문서 기준)
3. 아이디어: 점검 목록으로 활용 — IPv6 매핑/NAT64/6to4 내장 IPv4, 해석된 모든 주소 검사, 파싱 불가 시 거부, **요청 시점 IP 고정**
4. 이는 코드 이식이 아니라 Neodio 구현이 빠뜨린 케이스가 없는지 **테스트 케이스 목록**을 만드는 용도

## 버리는 아이디어 (이유 포함)

- 제3자 스크래퍼에 AI 챗봇 수집 위탁: 약관·가격 위험, Neodio P0 원칙(공식 API/자체 통제)과 충돌 → 06
- 브라우저 상태 저장, KV 덮어쓰기, 인터벌 스케줄러: SaaS 요건 미충족
- 가산식 점수 / 영어 감성 목록: Neodio가 이미 더 나음
