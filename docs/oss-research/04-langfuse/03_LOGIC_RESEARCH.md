# 03. LOGIC_RESEARCH — langfuse @ 728e693

> **정독 범위(§0)**: 수집 배치 처리(`processEventBatch`), 샘플링, 샤딩, 가격 티어 매칭, 평가 실행·오류 분류, 결정적 샘플링, 외부 URL 검증 일부, Prisma 스키마(프롬프트·평가·실행). 나머지(대시보드 쿼리 엔진, 인증, 과금, 모니터 실행 등)는 **미검증**. 코드·프롬프트 원문은 싣지 않는다. **ee 영역은 열람하지 않았다.**

## L1. 수집 파이프라인 (내구성 우선)

- 목적: 많은 이벤트를 잃지 않고 받아 비동기로 처리.
- 입력/출력: 이벤트 배열 → 부분 성공 결과(이벤트별 상태).
- 핵심 속성:
  - **먼저 원본 영속, 그 다음 큐** — 큐나 DB가 막혀도 원본은 보존.
  - 큐 페이로드는 참조만 → 큐 메모리/크기 한계 회피.
  - 객체 저장 실패는 "실패로 처리하되 치명 예외 전환"(전체 배치 중단), 스로틀은 별도 신호로 분류해 재시도 가능하게.
  - 테넌트 키 샤딩과 장애 테넌트 분리.
- 한계: 설계 복잡도 매우 높고 객체 저장소·Redis 모두 필수. 날짜 경계 지연 같은 휴리스틱은 환경 변수로 조정되는 임시방편 성격(코드 주석이 "비용/성능 트레이드오프, 재검토 필요"라고 인정).

## L2. 결정적 샘플링 (두 곳)

- 수집 샘플링: 트레이스 id의 SHA-256 앞 32비트를 [0,1]로 정규화 후 비율과 비교.
- 평가 샘플링: 도메인 문자열을 섞은 해시에서 53비트를 취해 [0,1] 값 생성(부동소수점 정밀도 때문에 53비트로 고정한 이유를 주석이 설명).
- 가치: **같은 대상은 항상 같은 결정**(재처리·재시도에도 일관), 상태 저장 불필요.
- 한계: 비율 변경 시 이전에 제외한 대상이 새로 포함될 수 있음(허용된 성질).

## L3. 가격 티어 매칭

- 모델 이름 패턴으로 모델 식별 → 사용량(예: 입력 토큰 합계)이 조건을 만족하는 **우선순위 첫 티어** 선택, 없으면 기본 티어.
- 사용량 키는 패턴(정규식)으로 합산 → 제공자마다 다른 사용량 필드 명칭 흡수.
- 조건 평가 중 예외는 "불일치"로 처리(안전 쪽 실패).
- 한계: 정규식을 데이터로 저장·실행(성능·악성 패턴 위험은 코드 상 제어 여부 **미검증**).

## L4. LLM-as-judge 실행

- 평가기 버전 불변 + 규칙이 연결 + 결정적 샘플링 + 실행 레코드 → 나중에 "어떤 버전이 이 점수를 만들었나"를 추적 가능.
- 출력 정의를 영속하고 스키마로 검증. 모델에게는 안전한 필드명으로 요청하고 나중에 계약 필드로 매핑(코드 주석이 "생각(thinking) 모델은 `reasoning`이라는 필드를 사고 공간으로 써서 점수를 누락시킨다"는 관찰을 기록).
- **테스트 실행과 실제 실행이 같은 함수**를 사용(테스트가 실제 요청과 동일한 입력을 보냄).
- 실패 처리: 오류를 구조화 정보로 먼저 분류하고, 구조 정보가 없을 때만 **메시지 패턴**으로 보조 분류. 종결성 오류(인증 무효·결제 소진·엔드포인트 불가·제공자 계정 미준비)는 **평가기를 정지**시켜 같은 실패가 대량 반복되는 것을 방지. 재시도 가능 여부는 제공자 정보가 우선.
- 한계: 패턴 문자열 매칭은 제공자 문구 변경에 취약. 판정 품질 자체를 측정하는 골드셋 기능은 코드에서 확인하지 못함(사람 라벨링 큐는 존재).

## L5. 프롬프트 관리 모델

- (프로젝트, 이름, 버전) 유일, 라벨 배열(예: 운영 라벨), **보호 라벨**(특정 라벨은 권한자만 변경), 커밋 메시지, 의존성(다른 프롬프트의 버전/라벨 참조).
- 한계: Neodio의 "추적 프롬프트 라이브러리"와 목적이 다름(이쪽은 LLM 앱의 입력 템플릿 관리).

## L6. 외부 URL 방어 — 연결 시점 검증

- 사전 검증: 인코딩 엄격 검사, 스킴, https 강제 옵션, URL 내 자격증명 금지, 포트 제한, 허용 목록, IP 리터럴 처리.
- DNS: 여러 해석 경로(A·AAAA·시스템 해석 `lookup`)를 모두 모아 검사 — **런타임 fetch가 쓰는 경로와 같은 소스를 포함**.
- **연결 계층 재검증**: 요청을 보내는 에이전트가 연결 시 해석된 IP를 다시 검증하는 구조 → 검사와 연결 사이의 DNS 변경(TOCTOU)을 구조적으로 차단. 에이전트 풀 크기 상한과 정책별 캐시.
- 한계: 프록시 환경에서의 예외 처리 규칙(우회 목록) 등 복잡성. 전체 정독 안 함.
