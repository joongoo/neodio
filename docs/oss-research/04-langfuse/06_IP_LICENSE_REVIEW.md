# 06. IP_LICENSE_REVIEW — langfuse

> 법률 자문이 아니다. 법률 판단이 필요한 항목은 **승인 보류**.

## 1. 라이선스 구조 (이번 프로젝트의 핵심 위험)

| 영역 | 라이선스 | 처리 |
|---|---|---|
| 루트 `LICENSE`가 적용되는 대부분 | MIT (Copyright 2023-2026 ClickHouse, Inc.) | 아이디어 연구만, 코드 이식 정책상 금지 |
| `ee/`, `web/src/ee/`, `worker/src/ee/`, `packages/shared/src/server/ee/` | **Langfuse Enterprise License** (상업, 유효한 계약 없이는 사용 불가) | **열람·참조·재현 모두 하지 않음.** 이 분석에서 `ee/` 경로 하위 파일은 읽지 않았고(라이선스 본문 상단과 디렉터리 목록만 확인), 05에 해당 영역 유래 내용 없음 |
| 서드파티 구성요소 | 각자의 원 라이선스 | 이식 안 함 |

- ⚠ 경계가 헷갈리는 항목: `packages/shared/src/server/` 아래의 일부는 `ee/` 하위에 있다(예: `.../server/ee/licenseCheck`). 이번에 정독한 파일은 `ingestion/`, `redis/sharding`, `pricing-tiers`, `evals/`, `outbound-url/`로 **`ee/` 경로 밖**임을 경로로 확인했다. 단, 내부 import 관계를 모두 추적하지는 않았다(**미검증**).
- 일부 기능(감사 로그, SSO 강제, 보존 정책 등)이 상업 영역에 속할 수 있다. **Neodio가 유사 기능을 만들 때는 원본 구현을 보지 않고 05의 일반 요구사항에서 시작**해야 한다. 어떤 기능이 `ee`인지는 **미확인**.

## 2. MIT 영역의 의무와 우리 정책

MIT는 고지 유지 조건으로 자유로운 사용을 허용하지만, 이번 프로젝트 정책은 "코드 비복제, 독립 재설계"다. 따라서 코드는 가져오지 않는다.

## 3. 보호 대상 (일반론)

| 대상 | 판단 |
|---|---|
| 소스, 주석(특히 설계 의도를 길게 설명한 주석) | 표현 → 복제 금지 |
| **평가기/판정 프롬프트 원문 및 내장 평가 템플릿** | 열람하지 않았음. 05는 자체 요구로 작성 |
| Prisma/ClickHouse 스키마 구성 | 개별 구조는 기능적이나 전체 구성은 표현 가능 → 05는 다른 개념 단위(판정 프로필·실행 원장·유효일 단가표)로 설계 |
| 가격표·모델 정규식 데이터 | 열람 일부. 05는 정규식 방식을 채택하지 않음 |
| 아이디어(결정적 샘플링, 종결성 오류 정지, 불변 버전, 연결 시점 IP 검증, 원본 우선 영속) | 일반 개념. 단 법적 판단은 변호사 |

## 4. Clean-Room 수행의 한계 (정직한 기록)

- 같은 세션·같은 에이전트가 원본 읽기와 설계를 모두 수행했다. 엄격한 Clean-Room이 아니다.
- 05는 구현 식별자·상수·환경변수·스키마 이름을 사용하지 않았다. 다만 **결정적 샘플링의 해시 기반 [0,1] 변환, 연결 시점 IP 검증, 불변 버전**은 원본과 개념을 공유한다(일반 기법).
- 구현 단계에서는 05만 읽는 새 세션이 담당하고, 구현 후 구조 유사성 점검을 수행한다.

## 5. 상표·서비스 관련

- "Langfuse" 이름·로고는 사용하지 않는다.
- **제품 도입(I8)**: Langfuse를 관측 도구로 도입하는 것은 코드 이식이 아니라 서비스 이용이다. 클라우드 이용 시 고객 콘텐츠 전송·보존 정책, 자체 호스팅 시 `ee` 기능 이용 금지·라이선스 준수가 필요. **이용 약관·DPA 미검증** → LEGAL_REVIEW 후보.
