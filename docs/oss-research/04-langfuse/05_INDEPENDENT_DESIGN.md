# 05. INDEPENDENT_DESIGN — Neodio 독립 설계 명세 (프로젝트 4 결과)

> **원본 소스·파일명·식별자·스키마 이름·상수·환경변수를 참조하지 않는다.** 04의 I1~I5만을 입력으로 작성. 새 모듈이 아니라 **기존 설계(D1, D4, D5)에 대한 보강 요구사항과 신규 보안 모듈 1개**로 구성한다.

## D5 보강 — 조직 격리 요구사항

기존 D5(내구성 있는 잡 엔진)에 다음을 추가한다.

- R-A1 **격벽(bulkhead)**: 조직별 동시 실행 상한 외에, 특정 조직에서 연속 실패가 기준(초기 제안: 최근 N건 중 M건)을 넘으면 그 조직의 작업을 **격리 레인**으로 옮기고 낮은 우선순위로 처리. 다른 조직의 처리량에 영향을 주지 않는다.
- R-A2 **참조 전달**: 작업 페이로드에는 대용량 본문을 싣지 않고 식별자만 둔다. 본문은 영속 저장소에 있고 작업은 그 참조를 읽는다.
- R-A3 **원본 크기 경계**: 단일 응답/HTML이 기준 크기(초기 제안 256KB)를 넘으면 객체 저장소로 분리하는 경로를 열 수 있도록 저장소 인터페이스를 추상화. 지금은 DB 저장 유지 가능.
- R-A4 **부분 성공 보고**: 배치 결과는 항목별 {성공, 오류코드, 재시도 가능 여부}.
- R-A5 **결정적 표본**: 부하 조절·평가 비용 조절을 위한 표본 선택은 대상 식별자 기반 결정적 함수를 사용. 같은 대상은 항상 같은 결정, 비율이 바뀌어도 설정 이력과 함께 기록.
- R-A6 **샤드 확장 대비**: 큐 키에 조직 식별자를 포함해, 나중에 물리적 분리(큐/DB 분리)가 가능하도록 한다.

**검증**: 한 조직에 지속 실패를 주입한 상태에서 다른 조직의 대기 시간(p95) 증가가 기준 이내, 재시작 후 작업 손실 0.

## D4 보강 — 판정기 거버넌스

기존 D4(답변 평가기)의 `eval_profile`을 다음 요구로 확장한다.

- R-B1 **불변 버전**: 판정 지침, 모델, 샘플링 설정, 출력 스키마는 한 번 만든 버전은 수정할 수 없고 새 버전만 만든다.
- R-B2 **실행 원장**: 모든 판정은 {판정 버전, 대상, 상태[대기/실행/성공/오류/취소], 비용, 시작·종료, 오류코드} 행을 남긴다.
- R-B3 **종결성 오류 정지**: 오류를 {일시적, 영구(인증/한도/엔드포인트/계정), 정책 거부}로 분류한다. 영구 오류가 N회 연속이면 판정 프로필을 **정지 상태**로 전환하고 사유를 저장·알림. 정지 상태에서는 새 판정을 시작하지 않는다.
- R-B4 **분류 계약**: 오류 분류는 어댑터가 반환하는 구조화 코드가 우선이며, 문자열 패턴은 마지막 수단이고 패턴 사용 시 지표로 계수해 구조화 코드 누락을 추적한다.
- R-B5 **시험/실제 동일 경로**: "시험 실행"은 실제 판정과 같은 함수·같은 입력 조립을 사용하고, 결과를 저장하지 않을 뿐이다.
- R-B6 **표본 판정**: 비용 한도 내에서 표본 비율로 판정할 수 있으며, 표본 판정으로 만든 지표는 화면에서 표본임을 표시한다.
- R-B7 **출력 계약 점검**: 판정 모델에 요청하는 출력 필드 구성이 모델 동작에 영향을 줄 수 있으므로, 새 모델 도입 시 골드셋 소규모 점검을 통과해야 활성화한다.

**데이터(제안)**: `judge_run(id, profile_id, target_ref, state, error_class, cost_usd, started_at, finished_at)`, `judge_profile.status[active|paused]`, `judge_profile.pause_reason`.

**검증**: 키 무효화·한도 소진 주입 시 정지 전환 및 알림, 정지 중 새 호출 0건.

## D1 보강 — 단가표

- R-C1 단가표는 **유효 시작일 이력** 보관. 과거 실행의 비용은 당시 단가로 재현 가능해야 함.
- R-C2 모델 식별은 **정확한 식별자 + 별칭 목록**으로 한다(패턴 매칭을 데이터로 저장하지 않음).
- R-C3 사용량 조건에 따른 티어(예: 입력 길이 구간)를 지원. 조건은 닫힌 형식(필드, 비교 연산, 값)만 허용.
- R-C4 단가가 없는 모델은 비용 미상 상태로 표시하고 예산 예약 시 **상한 추정치**를 사용한다(0원 처리 금지).
- R-C5 사용량 필드 명칭은 어댑터 계층에서 표준 이름으로 정규화한 뒤 계산.

## D10. 안전한 외부 요청 모듈 (Safe Outbound Fetch)

**목표**: 서버가 사용자·브랜드가 지정한 URL을 가져오는 모든 지점에서 내부망 접근을 구조적으로 차단한다.

**요구사항**
- R1 **단일 진입점**: 서버의 외부 URL 가져오기는 이 모듈만 통해야 한다(직접 fetch 금지를 린트 규칙으로 강제).
- R2 사전 검증: 스킴 제한(기본 https만, 필요 시 http 허용 설정), URL 내 자격증명 금지, 포트 허용 목록, 호스트 이름 엄격 정규화, 인코딩 이상 거부.
- R3 이름 해석: 런타임 요청이 사용할 해석 경로와 동일한 경로를 포함해 모든 주소를 수집하고, 하나라도 비공개·예약 대역이면 거부.
- R4 **연결 시점 검증**: 실제 연결 직전에 확정된 IP를 다시 검증하고, 검증을 통과한 그 IP로만 연결한다(검사와 연결 사이 이름 해석 변경 차단).
- R5 리다이렉트마다 R2~R4 재적용, 횟수·총 시간·응답 크기 상한.
- R6 IPv6의 IPv4 내장 표현, 변환 주소 대역 등 우회 표현을 모두 정규화해 검사. 해석 실패·파싱 실패는 거부(fail-closed).
- R7 거부 사유는 구조화 코드로 반환(운영 지표 집계용). 사용자 메시지에는 내부 정보를 노출하지 않는다.
- R8 조직별 허용 도메인 모드: 브랜드에 등록된 도메인만 허용하는 정책을 옵션으로 제공(현재 방식 유지 가능).

**검증**: 우회 표현 테스트 세트(IPv4 정수/16진/8진 표기, IPv6 매핑, 점 없는 호스트, 유니코드 호스트), 리바인딩 시뮬레이션, 리다이렉트 체인 테스트.

## D11. (요구사항 기록) 데이터 보존·삭제

- 조직/브랜드 단위 보존 기간, 원본 응답과 파생 지표 구분, 삭제 요청의 감사 기록, 삭제 가드(대량 삭제 시 확인), 삭제 후 재집계 정책.
- 법무 요건(제3자 콘텐츠 보존, 개인정보)이 정해진 뒤 별도 설계. 이번 범위에서는 요구사항만 기록.
