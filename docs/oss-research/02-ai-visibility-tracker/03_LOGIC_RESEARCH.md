# 03. LOGIC_RESEARCH — ai-visibility-tracker @ fad7d13

구현 코드·프롬프트 원문은 싣지 않는다. 읽은 파일 기준, 미확인은 "미검증".

## L1. 브랜드 언급 감지 — `services/geo/parser.ts`

- 방식: 소문자화 후 **부분 문자열 포함** 검사(브랜드명·도메인·별칭 중 하나라도 포함이면 true). 이진 값만 반환(횟수·위치 없음).
- 한계: 단어 경계가 없어 짧거나 일반명사형 브랜드가 다른 단어 안에서 오탐 가능(영문 기준). 언급 위치/순서 정보가 없어 "얼마나 눈에 띄는가"를 못 잰다. 한국어는 부분 문자열이라 조사 문제는 없지만 오탐 위험은 오히려 큼(미검증).

## L2. 인용 추출·도메인 — `parser.ts`

- 인용은 OpenRouter 응답의 URL 인용 주석에서만 가져옴(본문 내 URL은 안 봄). 호스트는 소문자 + `www.` 제거.
- 자사 판정: **호스트 일치 또는 점 + 자사 도메인으로 끝남**(서브도메인 허용). 부분 문자열 포함이 아니라 접미사 규칙이라 정확도가 높다(앞 프로젝트보다 우수).
- 한계: 공개 접미사(co.kr 등)·추적 파라미터·단축 URL 정규화는 이 경로에 없음(별도 `url-host.ts` 17줄, 얕음).

## L3. LLM 구조화 채점 — `services/geo/scorer.ts` (핵심 아이디어)

- 목적: 정규식으로 못 잡는 **추천 여부, 추천 순위, 경쟁사 목록·추천·순위, 브랜드 사실 반영도**를 LLM으로 추출.
- 입력: 응답 원문 + "브랜드 지식"(우선 사실, 거래 중단 요소, 차별점, 속성)을 마크다운화한 컨텍스트 + 경쟁사 이름.
- 출력(JSON): 정확도·커버리지·감성(0–100), 추천 여부/순위, 속성별 "인정됨" 여부+증거, 경쟁사별 추천/순위/속성, 서술 이유. 합성 점수 계산.
- 장점: 브랜드 사실 기반 채점(환각/오정보 탐지 가능), 경쟁사까지 한 번에 구조화.
- 한계: ① 단일 판정·검증 세트 없음 → 정확도 미보증 ② "증거"는 자유 서술이고 **원문 구간(span) 인용을 강제하지 않아** 사후 검증 어려움 ③ 응답 1건당 LLM 호출 1회 추가 → 비용 2배 ④ 판정 모델 변경 시 과거와 비교 불가(모델명만 저장, 프롬프트/판정 버전 없음) ⑤ JSON 파싱 실패 시 바깥 중괄호 구간을 잘라 재시도하는 단순 복구 ⑥ 영어 프롬프트 중심(한국어 응답 품질 **미검증**).

## L4. Share-of-Voice 스냅샷 — `services/geo/sov.ts`

- 정의: 날짜별, 브랜드별 **언급률·인용률·추천률** = 해당 브랜드가 나온 실행 수 / 채점 완료 실행 수. (브랜드들의 합이 100%가 되는 "점유율"이 아니라 각자 독립적인 **출현율**.)
- 자사 언급은 L1 부분 문자열, 경쟁사 언급은 L3 LLM이 뽑은 이름을 **정규화 후 이름/별칭 일치**로 매칭. → **자사와 경쟁사의 탐지 방법이 비대칭**(편향 원인).
- 경쟁사 인용은 호스트 일치로 판정.
- 분모가 "채점된 실행"이므로 채점이 일부 실패하면 분모가 줄어 비율이 흔들린다.
- 결과는 날짜별 행으로 저장(upsert) → 이후 정의가 바뀌어도 과거 스냅샷은 그대로(재계산 불가).

## L5. 의도 분류 — `services/geo/intent.ts`, `classify-prompts.ts`

- 두 축을 분리: **의도**(상업적/거래/정보/탐색) × **브랜드명 포함 여부**. 기존 한 필드가 "브랜드 포함 질의"와 "상업적 질의"를 섞어 거짓 정보를 준다는 이유를 코드 주석이 설명.
- 비용 통제: 상업적·거래 의도만 스윕 대상("상업적만" 모드). 휴리스틱(수식어 목록: B2C/B2B 모두) + LLM 분류 병용. 레거시 자유 텍스트를 정식 값으로 매핑.
- 한계: 수식어 목록이 영어 중심.

## L6. 지역 처리 — `locations.ts`, `local-qualifier.ts`, `dataforseo.ts`

- 엔진별로 지원하는 지역 단위가 다름(도시/국가/없음) → **실제 적용된 지역을 별도 컬럼에 기록**하고, 도시를 질문 문장에 녹여 넣은 경우 **실제 보낸 문장을 따로 저장**(재현성).
- 한계: 지역 판별 토큰이 호주·뉴질랜드·영국·캐나다·미국 지명 하드코딩 → 한국 사용 불가. 코드 주석상 엔진 단가와 엔드포인트는 특정 시점(2026-07-17) 실측.

## L7. 오케스트레이션 — `orchestrator.ts`

- 같은 날 이미 한 (프롬프트, 모델) 조합은 **건너뜀**(비용 절약), 수동 재확인만 덮어씀. 덮어쓸 때 오래된 경쟁사 언급을 즉시 삭제해 이중 집계를 방지.
- 빈 스윕은 "성공"이 아니라 **실패로 보고**(미설정 제공자/모두 필터됨 사유 명시) — 운영 신호 설계가 좋음.
- 한계: 하루 1회 표본 → LLM 비결정성을 확률로 다루기 어려움(Neodio는 반복 실행 가중이 있음).

## L8. 품질 신호

- 테스트 2개(미실행). 타입은 TS+Drizzle로 양호. 거대 라우터 파일(2,135줄)은 유지보수 위험. README와 코드 불일치(citation-gap).
- SSRF 가드: 사설 IPv4 대역 7개 + IPv6 확장 처리, 파싱 불가 시 거부. 앞 프로젝트보다 차단 범위가 좁고(예약/문서/멀티캐스트 대역 일부 누락) TOCTOU는 명시적 미해결.
