## 추출 방법

- 운영 DB를 `BEGIN READ ONLY`(`transaction_read_only = on` 확인) + SELECT만으로 조회하고 마지막에 ROLLBACK. 쓰기·비밀 값 출력 없음.
- 모집단: 성공 수집 실행 657건 × 그 프롬프트가 추적하는 브랜드의 (자사 + 등록 경쟁사) = 후보 쌍 7,512개. **항목 단위 = (응답, 대상 브랜드)**.
- 난수 시드 20261105로 재현 가능.
- 층화: 역할(자사/경쟁사) × 규칙 기반 언급 여부(있음/없음)를 4칸으로 나눠 60/40/60/40건을 배정. 각 칸 안에서 (조직, 플랫폼, 길이 3분위) 그룹을 돌아가며 뽑고, 한 응답에서 최대 2건, 경쟁사 한 곳이 칸의 20%를 넘지 않게 제한.
- **어려운 사례 우선 배정**(칸 정원의 약 35%): 언급이 있는 칸은 별칭으로만 일치 / 조사가 붙은 일치 / 응답 후반부의 단 한 번 언급 / 단 한 번 언급, 언급이 없는 칸은 공백·기호를 지우면 이름이 나오는 근접 미탐 후보.

## 한계 (정직한 기록)

1. **모집단이 작다**: 조직 2곳, 657건. 한 조직이 자사 브랜드로 데모성 브랜드를 포함. 일반화에 한계.
2. **어려운 사례가 풀 자체에 적다**: 조사 부착 5건, 근접 미탐 1건뿐 — 후보가 그만큼밖에 없었다. 현재 데이터에서 위험한 경계 사례가 드물다는 점은 00a의 오탐 0건 결과와 일치한다. 이 부분을 시험하려면 **합성 어려운 사례를 추가**해야 한다(D7 시험용, 별도 작업).
3. **표본 크기**: 200건이면 비율 추정 오차가 대략 ±7%p(50% 근처, 95%)다. 이번 파일럿의 목적은 정확도 측정이 아니라 **지침 모호성 탐지와 라벨러 일치도 확인**이다.
4. **짧은 응답이 적다**(16건): 모집단에서 짧은 응답의 대상 쌍이 적어서다.
5. 일치도 도구의 카파는 한쪽 범주만 쓰인 열(예: 모두 '예')에서는 정의되지 않아 '-'로 표시된다.
6. 규칙 기반 판정이 "언급 없음"인 항목 중 실제 언급이 있었던 경우(**규칙의 미탐**)를 보려면 사람이 80건의 비언급 항목을 봐야 한다 — 이 칸이 규칙 재현율 측정에 쓰인다.

## 진행 순서 (제안)

1. 라벨러 2명 지정(네오다임 직원, 서로 독립) → 각자 50행씩 4회에 나눠 작업
2. `node compute_agreement.cjs labeling_sheet.csv` 로 열별 일치율/카파 확인
3. 일치도가 낮은 열의 정의 개정 → 불일치 항목 조정 회의
4. 조정 결과를 **골드셋 v0**(D13의 첫 버전)로 확정, KEY 파일과 결합해 규칙 기반 판정의 정밀도·재현율 측정(D7·D8·D4 기준선)
