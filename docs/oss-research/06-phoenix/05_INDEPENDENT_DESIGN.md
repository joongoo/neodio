## D13. 골드셋 및 판정기 보정 체계 (Gold Set & Judge Calibration)

**목표**: D4·D6·D8 같은 의미 판정기가 지표에 반영되기 전에, 사람이 라벨링한 대표 데이터로 **정확도를 측정·게이트**하고, 판정기 변경마다 같은 기준으로 회귀 검증한다.

### 구성 요소

**(1) 골드셋 (Gold Set)**
- R1 골드셋은 버전을 가진다. 라벨 추가·수정·삭제는 새 버전을 만들고 이전 버전은 불변.
- R2 항목 = {응답 참조(prompt_run), 브랜드, 판정 대상 질문(예: 추천 여부, 순위, 입장, 신원), 정답 라벨, 라벨러 기록}.
- R3 **분할**: 개발용 / 검증용 / 봉인용. 봉인용은 지침 개정 과정에서 열람 불가(권한으로 강제)하고 배포 승인 시에만 사용.
- R4 **층화 표본 추출**: 엔진, 마켓/언어, 브랜드 유형(일반명사형, 약어, 동명 존재 등), 언급 유무, 답변 길이 구간으로 층화. 어려운 사례 쿼터 지정.
- R5 **이중 라벨링**: 최소 2인이 독립 라벨, 불일치는 조정자가 결정하고 조정 이력 보존. 라벨러 간 일치도를 항목 유형별로 계산해 낮으면 판정 정의 문서를 먼저 개정.
- R6 **능동 선택**: 라벨링 우선순위 큐는 규칙 기반 결과와 판정기 결과가 불일치하거나 판정기 확신도가 낮은 항목을 먼저 노출.
- R7 개인정보·제3자 콘텐츠 점검 표시와 보존 기한(D11 연동).

**(2) 판정기 보정 리포트 (Calibration Report)**
- R8 입력: 판정 프로필 버전 + 골드셋 버전 → 출력: 클래스별 정밀도, 재현율, F-beta(지표별 beta 사전 지정), 혼동 행렬, 언어/엔진/브랜드 유형별 분해, 각 수치의 신뢰구간(D2 방식).
- R9 **활성화 게이트**: 판정 프로필은 핵심 지표가 합의된 기준을 충족해야 `active`가 될 수 있다. 기준은 지표별로 문서화(오탐이 더 해로운 지표는 정밀도 하한, 누락이 더 해로운 지표는 재현율 하한).
- R10 **회귀 게이트**: 새 프로필 버전은 현행 활성 버전보다 핵심 지표가 악화되지 않아야 교체 가능. 악화가 있으면 사유와 승인 기록 필요.
- R11 **드리프트 점검**: 운영 중 주기적으로 소규모 신규 표본을 라벨링해 보정 지표 변화를 감시.

**(3) 불일치 기반 2차 판정 (선택)**
- R12 1차 판정 확신도 또는 규칙 기반과의 불일치가 기준을 넘을 때만 다른 모델로 2차 판정. 두 판정이 합의하면 채택, 갈리면 `불명` 상태로 저장하고 사람 검토 큐로 전송.
- R13 `불명`은 점수에 0으로 넣지 않고 **미측정**으로 취급해 분모에서 제외(별도 비율 표시).
- R14 2차 판정은 D1 거버너 예산을 통과하며, 가중 평균 점수는 만들지 않는다.

**(4) 판정 실행 증거 (D4 R-B2 확장)**
- R15 판정 실행 레코드에 보존: 입력 참조, 실제 전송 문서(D12 처리 후), 모델 응답 전문, 파싱 결과, 근거 구간 검증 결과, 지연, 재시도 횟수, 비용.

### 데이터 모델 (제안)
- `gold_set(id, version, purpose, created_at, frozen)`
- `gold_item(set_id, item_id, run_ref, brand_id, question_type, split[dev|val|sealed], strata_json)`
- `gold_label(item_id, labeler, label, labeled_at, adjudicated, adjudication_note)`
- `calibration_report(id, profile_id, gold_set_id, metrics_json, passed, created_at)`
- `review_queue(id, target_ref, reason[disagreement|low_confidence|drift_sample], state)`

### 인터페이스 (제안)
- `sampleForLabeling(strata, quota) → items`
- `computeAgreement(setId, questionType) → {kappa, byType}`
- `calibrate(profile, goldSet) → CalibrationReport`
- `canActivate(profile) → {ok, reasons}`

### 검증
- 골드셋 크기에 대한 신뢰구간이 기준 폭 이내인지(표본 부족이면 활성화 불가)
- 알려진 오판 샘플 주입 시 리포트가 열화를 감지
- 봉인 분할 접근 로그가 비어 있음(개발 단계)
- 라벨러 일치도가 낮은 유형에서 판정 활성화가 막힘
