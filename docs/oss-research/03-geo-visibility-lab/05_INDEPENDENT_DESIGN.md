## D7. 브랜드 매칭 엔진 v2 (Script-Aware Brand Matcher)

**목표**: 한국어·영어·일본어 혼합 환경에서 브랜드·별칭 일치의 오탐/미탐을 줄이고, 모든 일치에 설명 가능한 근거를 남긴다.

**요구사항**
- R1 입력 정규화: 호환 문자 통일(전각/반각 등), 대소문자 접기, 연속 공백 축소. **원문 오프셋을 보존**(근거 표시용).
- R2 별칭을 문자 체계 유형으로 분류: 한글 / 라틴·숫자 / 한자·가나 / 혼합.
- R3 유형별 경계 규칙:
  - 한글: 뒤에 오는 조사·어미 허용 목록을 별도 사전으로 관리(현 방식 유지·확장), 앞은 한글 연속 문자와 결합하지 않을 것(예: 복합명사 중간 일치 방지 여부는 골드셋으로 결정)
  - 라틴·숫자: 앞뒤가 영숫자일 때 불일치. 짧은 별칭(길이 기준 초기 제안 4자 이하)은 추가로 대소문자·주변 문맥 조건 선택 적용
  - 한자·가나: 부분 일치 허용하되 별칭 길이 하한
  - 혼합: 경계는 가장자리 문자 유형을 기준으로 적용
- R4 겹치는 일치는 긴 별칭 우선으로 병합, 같은 위치는 한 번만 집계.
- R5 일치 결과는 별칭별 {시작·끝 오프셋, 매칭 규칙 id, 스니펫}를 보존. 스니펫 길이는 문자 수가 아니라 문장 경계를 우선.
- R6 위험 별칭 진단: 최근 N일 일치 중 사람이 "오탐"으로 표시한 비율, 평균 일치 길이, 일반 단어 사전 충돌 여부로 위험도 산출 → 브랜드 관리 화면에서 별칭 정리 제안.
- R7 **규칙 버전**을 기록한다. 규칙이 바뀌면 새 분석 버전으로 재분석하고, 과거 결과와 병합하지 않는다(기존 분석 버전 체계 사용).
- R8 배포 전 **그림자 실행**: 기존 데이터에 새 규칙을 적용해 결과 차이(새로 일치/사라진 일치)를 목록으로 출력하고 사람이 샘플 검토 후 승인.

**데이터 모델(제안)**
- `match_rule_version(id, rules_hash, created_at, notes)`
- `brand_match_span(observation_id, alias_id, start, end, rule_id, snippet)`
- `alias_risk(alias_id, window_days, false_positive_rate, common_word_conflict, computed_at)`
- `match_review(span_id, reviewer, verdict[correct|false_positive|ambiguous], reviewed_at)`

**인터페이스(제안)**
- `match(text, aliases, ruleVersion) → Span[]`
- `shadowCompare(ruleVersionA, ruleVersionB, filter) → DiffReport`
- `aliasRisk(brandId) → AliasRisk[]`

**검증**: 언어별 골드셋(오탐 후보·미탐 후보 각각 수십~수백 건), 규칙 변경마다 회귀 통과, 그림자 실행 차이 샘플 수동 점검.

## D8. 신원 신뢰도 (Identity Confidence)

**목표**: 일반명사형·동명 브랜드의 언급이 "정말 이 브랜드인가"를 증거 기반으로 등급화한다.

**요구사항**
- R1 입력: 매칭 스팬, 응답 내 인용 도메인(공식 도메인 여부), 정식 상호 동반, 브랜드가 선언한 사업 키워드·제품명 동반, 주변 문맥.
- R2 출력: 언급 단위 {등급(확정/개연/미확인), 증거 종류 목록}. 증거 종류는 닫힌 집합으로 관리.
- R3 **초기에는 지표에 반영하지 않는다.** 등급 분포를 별도 지표로 표시하고, 골드셋 정밀도 목표 달성 후 지표 반영 방식(제외/가중)을 별도 결정.
- R4 브랜드마다 "신원 위험도"(일반 단어 충돌, 동명 후보 존재)를 계산해 위험 브랜드에서만 강한 검증(D4 평가기 호출)을 수행해 비용을 절약.
- R5 등급 규칙도 버전 관리(D7의 규칙 버전과 같은 체계).

**데이터 모델(제안)**: `identity_assessment(observation_id, span_id, grade, evidence_kinds[], rule_version)`.

**검증**: 동명/일반명사형 브랜드 표본에서 등급별 정밀도·재현율, 사람 검토와의 일치도.

## D9. 비교 가능성 키와 재현성 봉투 (Comparability & Provenance Envelope)

**목표**: 추세를 이어 그려도 되는 조건을 시스템이 명시적으로 판정하고, 각 실행이 어떤 조건으로 수행됐는지 증거로 남긴다.

**요구사항**
- R1 **비교 키** = (프롬프트 내용 해시, 엔진, 마켓, 수집 방식 버전, 분석 규칙 버전). 키 구성 요소는 추세 영향도에 따라 "필수 일치"와 "경고만"으로 분류.
- R2 추세 계산은 비교 키가 같은 구간끼리 연결하고, 키가 바뀐 지점은 **단절 표시**(데이터 삭제가 아님). 사용자가 원하면 "단절 무시" 보기를 제공하되 경고를 병기.
- R3 변경 영향 알림: 한 주 안에 비교 키가 바뀐 프롬프트 비율이 기준 이상이면 요약 카드에 안내.
- R4 **재현성 봉투**(실행 단위, 비밀 제외): 모델 식별자, 샘플링 설정, 웹 검색 사용 여부, 요청 지역·실제 적용 지역, 실제 전송 문장(원문과 다를 때), 토큰·비용, 수집 도구 버전.
- R5 어댑터는 **구조화 오류 코드**(제한/타임아웃/인증/파싱/정책/알 수 없음)를 반환한다. 문자열 매칭 분류는 금지. 미측정 상태는 0과 구분해 저장·표시.
- R6 치명 오류(인증·쿼터)는 같은 잡의 남은 호출을 중단하고 사유를 기록(D5 연동).

**데이터 모델(제안)**
- `comparability_key(id, prompt_hash, engine, market, collector_version, analysis_rule_version)`
- `prompt_run`에 `provenance_json`, `error_code` 추가(기존 `rawMetadata` 확장으로도 가능 — 구현 시 결정)

**검증**: 과거 프롬프트 편집 이력을 재생해 단절 지점이 기대와 일치, 구조화 오류 코드가 모든 어댑터에서 채워지는지 계약 테스트.
