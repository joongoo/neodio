# 03. LOGIC_RESEARCH — geo-visibility-lab @ c77c5ef

구현 코드·프롬프트 원문은 싣지 않는다. 정독한 범위: `domestic_geo.py` 대부분, `monitoring_runner.py`, 테스트 일부, `build_web_data.py` 일부. 프런트 JS는 미정독.

## L1. 증거 제한 질의 ("투명 복제")

- 목적: 모델이 학습 지식이 아니라 **제공된 검색 증거만** 근거로 답하게 하여, "이 증거가 주어지면 모델이 우리를 언급/추천하는가"를 측정.
- 입력: 질문, 검색 결과 N개(번호 부여). 출력: 본문 + 추천 목록(이름, 순위, 증거 id) + 사용 증거 목록.
- 강점: 모델이 근거 id를 반드시 달아야 하므로 **인용 유효성 검사**가 쉬움(존재하지 않는 id는 제거 — 테스트에서 확인).
- 한계: 측정 대상이 소비자 AI 제품이 아니라 "검색 API + 모델 API 조합"이라는 점(README 인정). 검색 순위가 사실상 노출을 결정하므로 **브랜드 가시성의 상당 부분이 검색 API 결과에 의해 결정**됨.

## L2. 브랜드 매칭 — 문자 체계 인지 — `brand_match_details`, `alias_spans`

- 정규화(NFKC, 대소문자 접기)한 뒤, **라틴 문자·숫자 별칭은 앞뒤에 영숫자가 없을 때만** 일치(약어가 다른 단어 안에서 오탐되지 않음 — 테스트 `highly` vs `HLY`). 한자(CJK) 별칭은 부분 일치.
- 별칭별 횟수, 중/영 이름 구분 보고, 주변 36자 스니펫 최대 5개 저장 → "왜 언급으로 셌는지"가 화면에서 추적 가능.
- 부정 맥락 단서(예: "~는 추천하지 않는다" 류 문구)가 같은 스니펫에 있으면 표시하고, 모든 언급이 부정 맥락이면 `negative_only`. **언급 수에는 그대로 포함**(경고용 플래그).
- 한계: 단서 목록이 중국어 중심, 단순 부분 문자열 포함 검사라 오탐/미탐 가능(검증 세트 없음).

## L3. 신원(동명 브랜드) 증거 — `score_answer`

- 언급이 있을 때 "정말 우리 회사인가"를 증거층으로 판단: ① 공식 도메인 인용됨 ② 정식 회사명 일치 ③ 핵심 사업어 동반 → 증거가 하나라도 있으면 `supported`, 별칭만이면 `alias_only`.
- 가치: 흔한 단어형 브랜드/동명 기업 구분. 한계: 규칙 수가 적고 가중치 없음, 별칭만 매칭된 경우를 어떻게 지표에 반영할지는 정의되지 않음(별도 표기만).

## L4. 점수 — "투명 복제 점수"

- 순위 점수 70% + 인용 점수 20% + 공식 출처 점수 10%(가중치 설정 가능).
  - 순위: 1위 100점에서 순위당 10점 감점. **언급은 됐지만 순위 없음은 고정 40점**. 미언급은 0점.
  - 인용: 사용 증거 개수 × 20, 상한 100. 공식 출처: 공식 도메인 인용 여부 이진.
- 의도: 어떤 계산인지 공개하고 "타사 사설 점수와 동일하지 않다"고 명시.
- 한계: 선형 감점·고정 40점은 임의 상수(보정 근거 없음). 순위 판정은 **모델이 직접 출력한 JSON**에 의존(규칙 검증 없음). 인용 개수 상한이 빨리 포화.

## L5. 실패 상태 분류와 "0이 아님" 원칙

- 상태: 성공/타임아웃/제한/구문 오류/API 오류/업스트림 불가. 실패 레코드는 지표를 만들지 않고, 요약에서 **분모를 "사용 가능 응답"으로** 하며 사용 가능 응답이 0이면 비율은 null(테스트 `unavailable_is_not_zero`).
- 분류는 오류 **문자열 매칭**(언어별 문구)에 의존 → 취약.

## L6. 질문 세트 버전 + 비교 가능성 지문 — `question_set_fingerprint`

- 비교에 영향 주는 필드(id, 언어, 시장, 각 질문의 id/트랙/의도/문구/태그/활성)만 정렬 직렬화해 해시. 같은 세트 id라도 지문이 다르면 추세를 이어 붙이지 않음("조용한 수정이 과거 추세를 오염시키는 것" 방지). 트랙 구분(`benchmark`/`discovery`)으로 고정 벤치마크와 탐색용 질문을 분리.
- 레거시 단순 목록은 "버전 없음" 스냅샷으로 읽기 전용 호환.

## L7. 실행 설정 스냅샷 / 사용량

- 온도, 최대 토큰, 타임아웃, 사고(thinking) 설정, 검색 모드·결과 수·제공자를 레코드에 보존. 키/헤더는 제외. 토큰 사용량은 허용 필드만 추출.

## L8. 비용 계획

- 계획 단계에서 `모델 수 × 질문 수`로 호출 수를 계산하고(드라이런 기본), README의 예측기가 월 비용을 계산. 가격 미확인 시 `unavailable`로 표시(추정값 은닉 금지).

## L9. 품질 신호

- 테스트 32개(순수 함수 중심: 정규화, 점수, 매칭, 상태, 질문 세트, 오류 변환, 스케줄 판정). CI에서 컴파일·단위 테스트·JS 문법·릴리스 게이트 실행. **실행은 하지 않았다(미검증)**.
- 타입 힌트 있음. 외부 호출은 단일 `post_json`에 모아 타임아웃 → 오류 변환.
- 약점: 단일 대형 모듈, 파일 기반 잠금의 만료 없음, 재시도 때 성공 모델 재호출.
