# 02. ARCHITECTURE_ANALYSIS — geo-visibility-lab @ c77c5ef

## 1. 구조

```
domestic_geo.py       수집·채점·요약 핵심(단일 파일 822줄): 검색 → 모델 → 채점 → 리포트
monitoring_runner.py  계획 확인(드라이런 기본) / 실행(--execute) / 잠금 파일 / 상태 파일
build_web_data.py     runs-by-provider/**/report.json을 모아 웹 데이터(JS)와 추세 생성
dashboard_server.py   루프백 전용 HTTP 서버 + 모니터링 설정 API(오리진·호스트 검증)
web/                  정적 대시보드 (중/영 전환)
scripts/              bootstrap, 데모 데이터 생성, 릴리스 점검
skills/, .claude-plugin/, .codex-plugin/   에이전트 배포 패키지
```

## 2. 데이터 흐름 (한 번의 수집)

1. 설정 파일에서 **활성 질문 세트**를 불변 스냅샷으로 읽고 지문(해시)을 계산
2. 질문마다: 검색 API 호출 → 상위 N개 증거(`S1..Sn` 번호) 정규화 → 모델 API에 "증거만 사용, 증거 인용 `[S1]`, JSON으로 답하라" 요청
3. 모델의 JSON(`본문`, `추천 엔티티[이름, 순위, 증거 id]`, `사용한 증거`)을 받아 로컬에서 채점
4. 질문별 레코드(상태, 지표, 인용 메타데이터, 토큰 사용량, 경과 시간) + 원본 모델 응답을 파일로 저장
5. 리포트 JSON/Markdown 생성 → 웹 데이터 빌더가 모델별 추세로 집계

## 3. 저장·격리·인증

| 항목 | 현황 |
|---|---|
| 저장 | 로컬 JSON 파일 트리(날짜/시각별 디렉터리). DB 없음 |
| 격리/멀티테넌트 | **없음**(단일 브랜드 설정) |
| 비밀 | 환경변수 또는 macOS 키체인에서만 읽음. 리포트·로그에 기록하지 않음(설계 원칙, AGENTS.md에도 명시) |
| 대시보드 보안 | 루프백만 허용, `Host`/`Origin` 검증으로 DNS 리바인딩·교차 출처 쓰기 차단(설정 API) |
| 검색 증거 | 리포트에는 **본문(passage)을 저장하지 않고** 위치·제목·URL·점수 같은 메타데이터만 보관(제공자 약관/저작권 배려로 보임, 의도는 **미확인**) |

## 4. 스케줄·잡

- 외부 스케줄러(cron/에이전트)가 `monitoring_runner`를 호출하는 구조. 자체 상주 프로세스 없음.
- "오늘 마감 시각이 지났고 오늘 완료 기록이 없으면 실행" → **재호출에 안전한 일 단위 멱등**. 일부 모델 실패 시 "완료"로 기록하지 않아 다음 호출에서 다시 시도.
- 동시 실행 방지: 배타적 생성(O_EXCL) 잠금 파일. 정상 종료 시 삭제. **프로세스가 강제 종료되면 잠금이 남는 구조**(만료 시각 없음).
- 이어달리기(resume): 질문 세트 id+지문이 일치할 때만 이전 성공 레코드를 재사용. 단 **러너는 resume 경로를 넘기지 않아** 재시도 때 이미 성공한 모델의 호출도 반복됨(비용 누수 가능, 코드 정독 근거).

## 5. 치명적 오류 단락(circuit break)

인증/리소스 오류 계열이 한 번 나오면 같은 실행의 남은 질문에 호출을 중단하고 "업스트림 불가"로 표시 → 불필요한 과금 방지.

## 6. 미구현·미확인

DB, 사용자/조직, 통계적 처리(표본 반복, 구간), 소비자 UI 수집, 경쟁사 비교(브랜드 1개 중심 — 경쟁사 필드 확인되지 않음), 한국어. 프런트 JS(687줄)는 **정독하지 않음**.
