## 1. 현재 공통 내비게이션 구조

현재 인증 후 화면은 `AppShell` 안에서 동일한 `TopBar`와 `Sidebar`를 사용한다.

- 전역 헤더: 로고, 조직·브랜드 전환, 알림, 사용자 메뉴
- 좌측 사이드바: 모든 업무 메뉴를 하나의 목록으로 표시
- tenant 화면: `/{org}/{brand}/...`
- global 화면: `/organizations`, `/users`, `/help`, `/dataforseo-poc`
- 권한별 메뉴: 사용자 관리와 DataForSEO PoC만 사이드바에서 조건부 노출

현재 사이드바 그룹은 앱 전환이 아니라 한 화면 안의 메뉴 구획이다.

## 4. 현재 확인된 권한·라우팅 특성

1. tenant 경로의 조직·브랜드는 URL이 기준이다.
2. 조직·브랜드를 바꾸면 같은 1차 화면 경로를 유지하지만 상세 ID와 Query Parameter는 유지하지 않는다.
3. 조직·브랜드가 없는 과거 tenant 화면 URL은 현재 tenant 경로로 리다이렉트한다.
4. 사용자 관리 화면은 메뉴 숨김뿐 아니라 페이지에서도 서버 권한을 검사한다.
5. DataForSEO PoC는 기능 플래그와 직원 권한을 함께 사용한다.
6. 브랜드 조회 권한과 편집 권한은 분리되어 있으며 읽기 전용 사용자는 공통 셸에서 안내된다.
7. 리포트, YouTube, 기회, 브랜드, 사용자 상세 화면은 상위 목록의 하위 경로로 존재한다.

## 6. 홈·가시성 개요·브랜드 가시성 분석

### 6.1 조사 대상

| 화면 | 경로 | 현재 메뉴 |
| --- | --- | --- |
| 개요 | `/{org}/{brand}` | 개요 |
| 가시성 개요 | `/{org}/{brand}/visibility-overview` | AI 가시성 > 가시성 개요 |
| 브랜드 가시성 | `/{org}/{brand}/brand-presence` | 브랜드 관리 > 브랜드 가시성 |

세 화면은 일부 KPI와 필터를 공유하지만, 현재 화면에서 수행하는 작업과 정보 밀도는 서로 다르다.

### 6.2 화면별 역할

#### 개요

사용자가 해결하는 주요 질문:

> 현재 브랜드의 전체 상태는 어떻고, 다음으로 어디를 확인하거나 설정해야 하는가?

현재 구성:

- 기간, 도메인, 플랫폼, 카테고리, 마켓, 질의 유형 필터
- 콘텐츠 가시성 상태
- 초기 설정·운영 체크리스트
- 가시성·언급·인용 등 핵심 지표
- 감성 분포 요약
- 마켓 비교 요약
- 트래픽 추이
- 최신 개선 기회
- 브랜드 가시성과 기회 화면으로 이동하는 CTA

판단:

- 분석 전용 화면보다는 서비스 전체 상태와 다음 행동을 안내하는 Action Hub에 가깝다.
- PM 목표 IA의 전역 `홈`에 가장 자연스럽게 대응한다.
- `감성 분포`와 `마켓 비교`는 브랜드 가시성의 요약이며, 상세 CTA도 브랜드 가시성으로 연결된다.
- `최신 기회`는 검색·콘텐츠 앱의 개선 기회로 이동하는 Cross-app 진입점이다.
- 별도의 `AI 가시성 대시보드`로 동시에 사용하면 전역 홈과 AI 앱 개요의 역할이 겹친다.

초기 제안:

- 화면과 경로를 그대로 유지하고 `홈`으로 분류한다.
- 분석 기능을 홈에 추가하지 않는다.
- 기존 요약 카드와 CTA의 목적지만 새 앱 명칭에 맞게 명확히 한다.
- 홈 화면 축소나 위젯 삭제는 이번 IA 범위에서 진행하지 않는다.

#### 가시성 개요

사용자가 해결하는 주요 질문:

> AI 답변에서 우리 브랜드와 콘텐츠가 어느 모델·마켓·토픽·출처에서 얼마나 노출되는가?

현재 구성:

- 기간, 마켓, 모델, 질의 유형 공통 필터
- 가시성·언급·인용 핵심 지표
- 모델별 언급 수·가시성
- 마켓별 언급 수·가시성
- 성과가 좋은 프롬프트 및 토픽
- 토픽 기회
- 최신 상위 브랜드
- 인용된 페이지
- 인용된 소스
- 소스 기회
- 토픽을 프롬프트 라이브러리에 추가하는 작업
- 브랜드 역할 분류와 소스 공략 추천 등록

판단:

- 단순 요약 대시보드가 아니라 AI 관측 결과를 토픽·브랜드·페이지·출처까지 탐색하는 분석 허브다.
- 브랜드 언급과 URL 인용 데이터를 한 화면에서 제공하지만, 각각의 표와 지표는 구분되어 있다.
- 현재 별도의 `인용 분석` 화면은 존재하지 않는다.
- `인용 분석`, `경쟁 분석` 메뉴를 목표 IA에 맞추기 위해 분리하면 기존 화면을 인위적으로 해체하거나 신규 화면을 만들어야 한다.
- Phase 1에서는 하나의 기존 화면을 그대로 재사용하는 것이 PM의 최소 변경 원칙에 부합한다.

초기 제안:

- AI 가시성 앱의 핵심 진입 화면으로 유지한다.
- 메뉴명은 `가시성 분석` 또는 `AI 가시성 분석` 후보로 둔다.
- 현재 포함된 인용 표는 화면 안에 유지하고 독립 `인용 분석` 메뉴는 만들지 않는다.
- AI 가시성 앱의 GNB 기본 진입점으로 사용한다.

#### 브랜드 가시성

사용자가 해결하는 주요 질문:

> 우리 브랜드가 경쟁 브랜드와 비교해 어떻게 변화하고 있으며, 어떤 토픽과 프롬프트에서 강하거나 약한가?

현재 구성:

- 기간, 마켓, 모델, 질의 유형 공통 필터
- 가시성·언급·인용 핵심 지표
- 경쟁 브랜드 선택
- 브랜드별 주간 언급률·인용률 비교
- 감성 분포
- 프롬프트 지표
- 응답 내 브랜드 배치 위치
- 모델 간 브랜드 노출 일관성
- 감성 판정 근거
- 모델·토픽 매트릭스
- 수집 품질
- 감성 개선·하락 상위 프롬프트
- 토픽별 데이터 인사이트
- Share of Voice

판단:

- 가시성 개요보다 경쟁 비교, 변화 추이, 감성, Share of Voice에 초점이 강하다.
- 독립적인 경쟁 브랜드 선택 상태와 다수의 상세 분석을 갖고 있어 단순 탭으로 흡수하기에는 화면 규모가 크다.
- `브랜드 관리`보다 AI 관측 결과를 분석하는 기능이므로 AI 가시성 앱이 더 적절하다.
- 현재 명칭은 브랜드 설정·CRUD 기능으로 오해할 수 있다.

초기 제안:

- 기능을 유지한 채 AI 가시성 앱으로 이동한다.
- 메뉴명은 `브랜드 비교`를 1순위로 제안한다.
- `경쟁 분석`은 실제 화면에 자사 브랜드의 감성·품질 분석도 포함되어 있어 범위가 다소 좁게 느껴질 수 있다.
- 가시성 개요와 통합하지 않는다.

| 기간 필터 | 있음 | 있음 | 있음 | 공통 |
| 마켓 필터 | 있음 | 있음 | 있음 | 공통 |
| 모델 필터 | 플랫폼 형태 | 있음 | 있음 | 명칭·옵션 정합성 추후 확인 |
| 질의 유형 | 있음 | 있음 | 있음 | 공통 |
| 감성 | 요약 | 없음 | 상세 | 홈 → 브랜드 비교 CTA 유지 |
| 브랜드 비교 | 요약 | 상위 브랜드·역할 | 시계열·SOV 상세 | 목적이 다름 |
| 인용 | KPI | 페이지·출처 상세 | 브랜드별 인용률 비교 | 데이터 관점이 다름 |
| 프롬프트·토픽 | 없음 | 성과·기회 및 추적 작업 | 변화·감성·SOV 분석 | 업무가 다름 |
| 개선 기회 | 최신 항목 요약 | 토픽·소스 기회 | 데이터 인사이트 | 검색·콘텐츠 앱 연결 필요 |
| 초기 설정 안내 | 있음 | 없음 | 없음 | 홈 고유 역할 |

공통 KPI와 필터만으로 세 화면을 중복 화면이라고 판단하기는 어렵다. 현재 기준으로는 다음 역할 분리가 가능하다.

```text
홈
  전체 상태 요약과 다음 행동

AI 가시성 > 가시성 분석
  모델·마켓·토픽·페이지·출처별 관측 결과 탐색

AI 가시성 > 브랜드 비교
  경쟁 브랜드 대비 변화·감성·점유율 분석
```

### 6.4 목표 IA와 현재 구현의 차이

| 목표 IA 메뉴 | 현재 구현 대응 | 처리 제안 |
| --- | --- | --- |
| 전역 홈 | 현재 개요 | 그대로 사용 |
| AI 가시성 대시보드 | 독립 화면 없음 | 신규 생성하지 않음 |
| 가시성 분석 | 현재 가시성 개요 | 기존 화면 매핑 |
| 인용 분석 | 가시성 개요 내부 표로 존재 | 독립 메뉴 생성하지 않음 |
| 경쟁 분석 | 브랜드 가시성이 일부 대응 | `브랜드 비교` 명칭 검토 |

AI 가시성 앱의 LNB가 적어 보이더라도 미구현 대시보드와 독립 인용 분석 화면을 채우기 위해 신규 메뉴를 만들지 않는다.

### 6.5 AS-IS → TO-BE 제안

| 기존 메뉴 | 기존 경로 | 신규 앱 | 신규 메뉴 | 처리 방식 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 개요 | `/{org}/{brand}` | 홈 | 홈 | 유지 | 제안 |
| 가시성 개요 | `/{org}/{brand}/visibility-overview` | AI 가시성 | 가시성 분석 | 유지·이동·명칭 변경 | PM 결정 필요 |
| 브랜드 가시성 | `/{org}/{brand}/brand-presence` | AI 가시성 | 브랜드 비교 | 유지·이동·명칭 변경 | PM 결정 필요 |

### 6.6 PM 결정 필요

1. `가시성 개요`의 메뉴명을 `가시성 분석`으로 변경할지
2. `브랜드 가시성`의 메뉴명을 `브랜드 비교`로 변경할지
3. 독립된 `AI 가시성 대시보드`는 만들지 않고 `가시성 분석`을 앱 기본 진입점으로 사용할지
4. 독립된 `인용 분석` 메뉴는 만들지 않고 가시성 분석 내부 표로 유지할지

### 6.7 현재 권장안

세 화면은 통합하지 않고 다음과 같이 역할을 분리한다.

```text
홈
  홈                         → 기존 개요

AI 가시성
  분석
    가시성 분석              → 기존 가시성 개요
    브랜드 비교              → 기존 브랜드 가시성
```

이 안은 화면·데이터·URL을 변경하지 않고 메뉴 소속과 명칭만 정리할 수 있어 가장 낮은 회귀 위험을 가진다.

## 7. 기회 개요·상세 화면 분석

### 7.1 조사 대상

| 구분 | 경로 | 현재 역할 |
| --- | --- | --- |
| 기회 목록 | `/{org}/{brand}/opportunities` | 발견된 기회와 진단 상태를 유형별로 표시 |
| 복잡도 | `.../opportunities/complexity` | 복잡한 콘텐츠 진단과 수정 가이드 |
| 콘텐츠 복구 | `.../opportunities/content-recovery` | JavaScript 의존 콘텐츠의 가시성 진단 |
| FAQ | `.../opportunities/faq` | FAQ 구조가 필요한 URL 진단 |
| 멀티미디어 | `.../opportunities/multimedia` | 이미지 alt 등 멀티미디어 진단 |
| robots.txt | `.../opportunities/robots-txt` | AI 에이전트 차단 및 사이트맵 상태 진단 |
| 구조화 데이터 | `.../opportunities/structured-data` | JSON-LD가 필요한 URL 진단 |
| 목차 | `.../opportunities/toc` | 문서 목차가 필요한 URL 진단 |
| 토픽 기회 | `.../opportunities/topic/[topic]` | 미언급 토픽의 콘텐츠·인용 추적 |

### 7.2 기회 목록의 현재 역할

사용자가 해결하는 주요 질문:

> 현재 브랜드의 AI 노출과 콘텐츠 접근성을 개선하기 위해 어떤 항목부터 조치해야 하는가?

현재 목록은 단순한 SEO 진단 목록이 아니라 다음 데이터를 한 진입점에서 연결한다.

- 사이트맵 크롤링 결과
- robots.txt 실시간 진단
- Google Search Console 상태
- AI 답변에서 발견된 미언급 토픽
- 프롬프트 라이브러리 등록 여부
- 토픽별 목표 콘텐츠 URL과 실제 인용 횟수
- URL별 제외 상태와 수정 가이드
- 재크롤 및 수정 완료 확인 결과

현재 카드는 두 섹션으로 구성된다.

#### 온사이트 콘텐츠 최적화

- 복잡한 콘텐츠 단순화
- 관련 FAQ 추가
- 멀티미디어 가시성 보강
- 목차 추가
- 구조화 데이터 추가
- 실측 결과에서 동적으로 발견된 토픽 기회

#### 온사이트 기술 최적화

- robots.txt로 차단된 트래픽
- 콘텐츠 가시성 회복

각 카드는 정상·주의·미확인 상태를 표시하고 독립 상세 경로로 이동한다.

### 7.3 상세 화면의 공통 구조

콘텐츠 진단 상세 화면은 공통적으로 다음 기능을 제공한다.

- 기회 목록으로 돌아가기
- 진단 대상 URL 수와 평균 지표
- 문제 설명과 개선 가이드
- URL별 상태 표
- Google 색인 상태
- PageSpeed 결과
- 해당하는 경우 GSC 리치 결과 상태
- URL별 재크롤·재검사
- 진단 대상 제외 및 다시 포함
- LLM 기반 수정 가이드 등록·조회
- 편집 권한에 따른 액션 제한

콘텐츠 복구는 여기에 최초·최신 크롤 결과의 전후 비교를 추가로 제공한다.

robots.txt 상세는 다른 진단과 UI 구조가 다르지만 업무 목적은 동일하다.

- robots.txt 원문과 차단 규칙
- GSC 사이트맵 처리 상태
- AI 에이전트별 차단 URL

토픽 기회 상세는 AI 관측과 콘텐츠 개선을 직접 연결한다.

- 프롬프트 라이브러리 추가
- 목표 콘텐츠 URL 등록
- 등록 URL의 실제 AI 인용 횟수
- LLM 기반 콘텐츠 생성 가이드
- 수집 로그별 언급·인용 변화
- Visibility Funnel

### 7.4 앱 소속 판단

`기회`는 AI 가시성에서 발견된 문제를 입력으로 사용하지만, 사용자가 화면에서 수행하는 주된 작업은 콘텐츠와 웹사이트를 진단하고 개선하는 것이다.

| 판단 기준 | 결과 |
| --- | --- |
| AI 답변·프롬프트에서 문제 발견 | AI 가시성과 연관 |
| URL·콘텐츠·robots.txt 상태 진단 | 검색·콘텐츠의 주 업무 |
| 콘텐츠 수정 가이드와 재크롤 | 검색·콘텐츠의 주 업무 |
| 목표 URL 등록 후 인용 재측정 | 두 앱을 연결하는 흐름 |
| 정식 메뉴 중복 필요 여부 | 없음 |

따라서 정식 메뉴 소속은 `검색·콘텐츠` 하나로 지정하고, AI 가시성에서는 Deep Link로 접근하는 것이 적절하다.

```text
AI 가시성
  가시성 분석
    토픽·소스·인용 문제 발견
      ↓ Deep Link

검색·콘텐츠
  개선 기회
    기회 상세
      콘텐츠 개선·목표 URL 등록·재측정
```

### 7.5 LNB와 상세 드릴다운 판단

현재 상세 화면들은 모두 다음 조건을 충족한다.

- 기회 목록의 카드 또는 분석 결과에서 진입한다.
- `콘텐츠와 기술 문제를 개선한다`는 상위 목적을 공유한다.
- 특정 진단 유형이나 토픽을 확인·조치하는 화면이다.
- 각 상세 화면을 독립 메뉴로 반복 접근할 필요는 낮다.

따라서 LNB에는 `개선 기회` 하나만 표시하고, 아래 항목은 모두 드릴다운으로 유지한다.

```text
검색·콘텐츠
  콘텐츠
    개선 기회              ← LNB
      복잡도                ← 상세
      콘텐츠 복구          ← 상세
      FAQ                   ← 상세
      멀티미디어            ← 상세
      robots.txt            ← 상세
      구조화 데이터         ← 상세
      목차                  ← 상세
      토픽 기회             ← 상세
```

### 7.6 현재 탐색 UX와 보완 필요 사항

현재 상태:

- 모든 상세 화면은 상단에 `기회 목록으로 돌아가기` 링크를 제공한다.
- 상세 경로에서도 현재 사이드바의 `기회 > 개요`가 활성화된다.
- 기회 목록에는 검색·필터·정렬·페이지 상태가 아직 없다.
- 브레드크럼은 없다.
- 일부 이동은 일반 `<a>`를 사용해 전체 페이지 탐색이 발생한다.
- AI 가시성에서 토픽 상세로 직접 들어와도 돌아가기 링크는 기회 목록으로 고정된다.

Phase 2 보완 후보:

1. 브레드크럼을 `검색·콘텐츠 > 개선 기회 > 상세명`으로 통일
2. LNB의 `개선 기회` 활성 상태 유지
3. 내부 이동 링크를 Next.js `Link`로 통일
4. 목록에 필터가 추가되면 Query Parameter로 상태 보존
5. AI 가시성에서 진입한 경우 안전한 내부 `returnTo` 또는 출처 링크 제공 검토
6. 브라우저 뒤로 가기와 고정 복귀 링크의 역할 구분

현재 목록에는 보존할 필터 상태가 없으므로, Phase 1에서 별도 상태 저장 기능을 먼저 만들 필요는 없다.

### 7.7 명칭 판단

현재 메뉴명 `기회`는 범위가 넓고, 목록 화면의 실제 행동인 진단·가이드·재검사를 충분히 설명하지 못한다.

후보 비교:

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| 기회 | 기존 명칭 유지 | 무엇을 할 수 있는지 불명확 |
| 개선 기회 | AI 관측과 콘텐츠 개선을 연결 | 일부 기술 진단에는 다소 추상적 |
| 콘텐츠 개선 | 직관적 | 토픽·robots.txt·기술 진단 범위를 축소해 보임 |
| 최적화 과제 | 실행 대상임이 명확 | 기존 제품 용어와 차이가 큼 |

PM 문서의 목표 IA와 현재 기능 범위를 함께 고려하면 `개선 기회`가 가장 적절하다.

### 7.8 AS-IS → TO-BE 제안

| 기존 메뉴 | 기존 경로 | 신규 앱 | 신규 메뉴 | 처리 방식 | 상태 |
| --- | --- | --- | --- | --- | --- |
| 기회 > 개요 | `/{org}/{brand}/opportunities` | 검색·콘텐츠 | 개선 기회 | 유지·이동·명칭 변경 | 제안 |
| 기회 상세 8종 | 기존 하위 경로 유지 | 검색·콘텐츠 | 개선 기회 드릴다운 | LNB 미노출·상위 활성 유지 | 제안 |

### 7.9 PM 결정 필요

1. 기존 `기회` 메뉴명을 `개선 기회`로 변경할지
2. 토픽 기회 상세의 정식 소속도 검색·콘텐츠의 개선 기회로 통일할지
3. AI 가시성에서 상세로 진입한 사용자를 위해 출처 화면 복귀 링크를 추가할지

### 7.10 현재 권장안

```text
검색·콘텐츠
  콘텐츠
    URL 인스펙터
    개선 기회              → 기존 /opportunities
```

- 기존 목록과 8개 상세 경로를 모두 유지한다.
- 진단 유형을 LNB 메뉴로 승격하지 않는다.
- AI 가시성에서는 기존 화면을 복제하지 않고 개선 기회 상세로 연결한다.
- Phase 1은 메뉴 소속과 활성 상태만 변경한다.
- 브레드크럼과 출처 복귀 UX는 Phase 2에서 별도로 적용한다.
