# Neodio 메뉴 및 앱 진입 구조 개편안

## 1. 개편 배경

현재 Neodio는 AI 가시성, 검색 분석, YouTube, 프롬프트 관리, 콘텐츠 진단, 운영 설정 등 성격이 다른 기능이 하나의 메뉴 안에 함께 노출되고 있습니다.

기능 확장에 따라 다음 문제가 나타날 가능성이 높습니다.

- 메뉴 수 증가로 원하는 기능을 찾기 어려움
- 분석 기능과 설정·운영 기능이 같은 위계에 혼재
- YouTube, GSC 등 채널별 업무 흐름이 분리되지 않음
- 상세 화면 진입 후 현재 위치와 복귀 경로가 불명확
- 신규 기능 추가 시 기존 메뉴 구조가 계속 복잡해짐

이에 따라 메뉴를 단순 재배열하는 수준을 넘어, 주요 업무 영역별로 앱 진입점을 구분하는 구조를 제안합니다.

---

## 2. 개편 방향

### 핵심 제안

**하나의 Neodio 서비스 안에서 주요 업무 영역을 독립된 앱처럼 구분합니다.**

- GNB: 앱 전환
- LNB: 선택한 앱의 기능 탐색
- 페이지 탭: 동일 기능 안의 세부 분석 기준
- 상세 화면: 메뉴 확장이 아닌 드릴다운으로 처리

별도의 서비스나 데이터베이스로 분리하지 않고, 인증·조직·브랜드·권한·공통 데이터는 현재처럼 공유합니다.

### 정보 구조 원칙

1. 사용자의 업무 목적을 기준으로 기능을 분류
2. 채널은 앱 또는 하위 메뉴 구분에 활용
3. DB 테이블 구조는 메뉴 분류 기준으로 사용하지 않음
4. 전체 메뉴는 최대 3뎁스로 제한
5. 상세 페이지는 메뉴 뎁스에 포함하지 않음

## 3. 목표 구조

### 3.1 전역 GNB

GNB는 다음 5개 앱 진입점으로 구성합니다.

| GNB | 역할 |
| --- | --- |
| 홈 | 전체 현황과 주요 알림을 확인하는 통합 허브 |
| AI 가시성 | AI 답변 내 브랜드 노출과 프롬프트 성과 분석 |
| 검색·콘텐츠 | 검색 성과와 웹 콘텐츠 상태 진단 |
| YouTube | YouTube AIO 모니터링과 영상 관리 |
| 관리 | 조직, 브랜드, 사용자, 데이터 연결 관리 |

조직·브랜드 선택, 통합 검색, 알림, 사용자 메뉴는 앱에 종속되지 않는 전역 기능으로 유지합니다.

### 3.2 전체 화면 구조

```text
┌──────────────────────────────────────────────────────────────────┐
│ Neodio │ 조직/브랜드 │ 홈 AI 가시성 검색·콘텐츠 YouTube │ 검색 │ 사용자 │
├───────────────┬──────────────────────────────────────────────────┤
│ 선택한 앱의   │ 브레드크럼                                      │
│ LNB           │ 페이지 제목                         기간·필터     │
│               │                                                  │
│ 섹션          │ 핵심 지표                                       │
│  메뉴         │                                                  │
│  메뉴         │ 차트·테이블·분석 결과                           │
│               │                                                  │
│ 섹션          │                                                  │
│  메뉴         │                                                  │
│               │                                                  │
│ 도움말·설정   │                                                  │
└───────────────┴──────────────────────────────────────────────────┘
```

## 4. 앱별 메뉴 구성안

### 4.1 홈

홈은 모든 기능을 다시 나열하는 화면이 아니라, 현재 상태와 다음 행동을 안내하는 허브로 구성합니다.

- 핵심 가시성 지표
- 브랜드별 주요 변화
- 검색 및 YouTube 이상 징후
- 최근 수집 상태
- 우선 확인이 필요한 개선 기회
- 최근 리포트
- 앱별 바로가기

`자세히 보기`에는 이동할 앱과 화면명을 함께 표시합니다.

예:

- `AI 가시성에서 자세히 보기`
- `검색 성과 확인`
- `YouTube 모니터링 열기`

### 4.2 AI 가시성

```text
개요
  AI 가시성 대시보드

분석
  가시성 개요
  브랜드 가시성

프롬프트
  프롬프트 리서치
  프롬프트 라이브러리
  프롬프트 전략

운영
  수집 실행
  리포트
```

프롬프트, 브랜드 언급, 인용, 가시성 지표는 동일한 관측 파이프라인을 공유하므로 하나의 앱 안에서 연결합니다.

### 4.3 검색·콘텐츠

```text
개요
  검색·콘텐츠 대시보드

검색 분석
  검색 트렌드
  검색 성과(GSC)

콘텐츠 진단
  URL 인스펙터
  개선 기회
```

`robots.txt`, 구조화 데이터, 콘텐츠 복구, FAQ 등의 진단 유형은 LNB에 개별 메뉴로 노출하지 않습니다. `개선 기회` 화면에서 유형별 카드와 필터를 통해 진입하도록 구성합니다.

### 4.4 YouTube

```text
개요
  YouTube 대시보드

분석
  AIO 모니터링

콘텐츠
  영상 관리

운영
  수집 이력
  채널 설정
```

YouTube는 데이터 구조와 사용자 업무 흐름이 다른 기능과 구분되므로 독립된 앱 진입점을 제공합니다.

### 4.5 관리

```text
워크스페이스
  조직 관리
  브랜드 관리

사용자
  사용자 및 권한

연결
  데이터 연결
  수집 설정

기록
  변경 이력
```

내부 검증 기능과 PoC 기능은 일반 메뉴에서 제외하고, 직원 권한에서만 표시되는 `운영 도구`로 분리합니다.

## 5. 뎁스 및 내비게이션 정책

### 5.1 권장 뎁스

| 단계 | UI | 용도 |
| --- | --- | --- |
| 0뎁스 | 전역 헤더 | 조직·브랜드·검색·사용자 컨텍스트 |
| 1뎁스 | GNB | 앱 전환 |
| 2뎁스 | LNB | 앱 내부 주요 기능 이동 |
| 3뎁스 | 페이지 탭 | 동일 기능의 분석 기준 전환 |
| 상세 | 드릴다운 | 개별 항목 확인 및 편집 |

권장 수량은 다음과 같습니다.

- GNB: 최대 5개
- 앱별 LNB: 최대 7~9개
- 페이지 탭: 최대 5개

### 5.2 LNB 정책

- 선택한 앱의 메뉴만 노출
- 메뉴 그룹은 접기·펼치기보다 고정된 섹션 라벨 사용
- 현재 선택 메뉴를 명확하게 강조
- 사용자 권한과 기능 활성화 여부에 따라 메뉴 제어
- 도움말과 설정은 LNB 하단에 고정

메뉴 수가 많지 않은 단계에서는 아코디언 사용을 최소화합니다. 접힌 메뉴는 사용자가 전체 기능 구조를 파악하고 위치를 기억하기 어렵게 만들 수 있습니다.

### 5.3 페이지 탭 정책

탭은 동일한 대상과 필터를 공유하는 경우에만 사용합니다.

적절한 예:

- 가시성 개요: `전체 / 모델별 / 마켓별`
- 검색 성과: `검색어 / 페이지 / 디바이스`
- YouTube 관리: `영상 / 프롬프트 / 수집 이력`
- 브랜드 설정: `기본 정보 / 채널 연결 / 수집 설정`

페이지의 목적이나 주요 데이터가 달라지면 탭이 아니라 LNB 메뉴로 분리합니다.

## 6. 상세 화면 개선안

현재 `자세히 보기` 이후 위치를 잃는 문제를 해결하기 위해 상세 화면을 다음과 같이 표준화합니다.

```text
검색·콘텐츠 > 개선 기회 > robots.txt 진단

← 개선 기회로 돌아가기

robots.txt 진단 결과
...
```

모든 상세 화면에 다음 요소를 제공합니다.

- 브레드크럼
- 명확한 이전 화면 링크
- 상세 진입 전 필터와 정렬 상태 보존
- 동일 목록의 이전·다음 항목 이동
- LNB의 상위 메뉴 선택 상태 유지

상세 화면은 새로운 메뉴로 추가하지 않고 목록 또는 대시보드에서 진입하는 드릴다운으로 취급합니다.

## 7. 통합 검색 제안

기능 증가에 대비해 전역 헤더에 통합 검색을 제공합니다. 단순 메뉴 검색이 아닌 명령 팔레트 방식이 적합합니다.

검색 대상:

- 메뉴 및 페이지
- 실행 가능한 기능
- 브랜드와 콘텐츠
- 최근 방문 화면
- 도움말

예시:

```text
“구글 연결” 검색

기능
  GSC 연결 설정

페이지
  검색 성과
  데이터 연결

도움말
  GSC 권한 설정 방법
```

메뉴의 정식 명칭뿐 아니라 사용자 표현과 동의어도 함께 검색해야 합니다.

## 8. 기대 효과

### 사용자 관점

- 현재 위치와 업무 영역을 쉽게 인지
- 자신과 관계없는 채널 메뉴 노출 감소
- 상세 화면 진입 후 복귀 경로 명확화
- 신규 사용자의 제품 구조 학습 부담 감소
- 검색을 통한 빠른 기능 접근 가능

### 제품 운영 관점

- 신규 기능을 적절한 앱에 안정적으로 추가 가능
- 권한과 요금제별 앱 노출 제어 용이
- 채널별 기능 확장에 유연하게 대응
- 향후 앱별 사용량과 전환율 측정 가능
- 기능 책임 영역과 개발 모듈 경계가 선명해짐

## 9. 적용 단계

### 1단계: 정보 구조 개편

- 기존 메뉴의 앱별 재분류
- GNB와 앱별 LNB 적용
- 기존 URL은 유지하거나 리다이렉트 제공
- 활성 메뉴 및 권한 정책 정리

### 2단계: 이동 경험 개선

- 브레드크럼 표준화
- 상세 화면 복귀 동선 개선
- 목록 필터 상태 보존
- 홈 화면의 `자세히 보기` 목적지 명확화

### 3단계: 통합 검색

- 메뉴·페이지 검색
- 기능 실행 검색
- 최근 방문 및 도움말 연동

### 4단계: 운영 최적화

- 앱별 이용률 측정
- 미사용 메뉴 및 중복 화면 정리
- 권한·요금제별 앱 노출 적용
- 실제 이용 패턴을 바탕으로 메뉴 명칭과 배치 조정

## 10. 최종 제안

Neodio는 기능별 페이지가 나열된 단일 메뉴 구조에서 벗어나, **업무 목적별 앱을 전환하는 통합 플랫폼 구조**로 개편하는 것이 적절합니다.

초기에는 시스템과 DB를 물리적으로 분리하지 않고, 하나의 서비스 안에서 다음 구조를 적용합니다.

> **전역 컨텍스트 → 앱 GNB → 앱별 LNB → 페이지 탭 → 상세 드릴다운**

이를 통해 현재 메뉴 복잡도를 낮추는 동시에, 향후 검색·YouTube·AI 가시성 기능이 확장되더라도 전체 내비게이션 구조를 안정적으로 유지할 수 있습니다.
