# GNB 제품 분류 및 조직별 제품 권한 검토안

## 1. 검토 결론

기존 GNB 체계는 유지하고, GNB 1Depth 중 업무 기능 영역을 제품으로 정의한다. 조직에 제품을 할당하면 해당 조직의 구성원에게 제품 진입 권한이 생기며, 기존 조직 역할과 브랜드 권한은 제품 내부의 조회·편집 범위를 계속 통제한다.

권한은 다음 순서로 판정한다.

`조직 접근 가능 → 제품 할당됨 → 브랜드 접근 가능 → 역할별 조회·편집 가능`

제품 권한은 계약·운영 범위이고, 사용자 역할은 제품 안에서 할 수 있는 행동의 범위이므로 두 권한을 분리한다.

## 2. GNB와 제품 분류

| GNB 1Depth | 제품 분류 | 조직별 할당 | 비고 |
| --- | --- | --- | --- |
| 홈 | 공통 | 미적용 | 할당된 제품의 요약과 진입점만 노출 |
| AI 가시성 | `AI_VISIBILITY` | 적용 | 가시성 분석, 브랜드 비교, 프롬프트, 수집 현황, 리포트 |
| 검색·콘텐츠 | `SEARCH_CONTENT` | 적용 | 검색 트렌드, GSC 성과, URL 진단, 개선 기회 |
| YouTube | `YOUTUBE` | 적용 | AIO 모니터링, 영상 관리 |
| 관리 | 공통 | 미적용 | 조직·브랜드·사용자·변경 이력 관리. 기존 역할에 따라 메뉴와 기능 제한 |

`홈`과 `관리`는 독립 판매 제품으로 두지 않는 것을 권장한다. 홈은 제품 진입 허브이고, 관리는 할당 제품과 사용자를 운영하기 위한 공통 기능이기 때문이다.

## 3. 권한 정책

| 구분 | 통제 대상 | 관리 주체 | 적용 방식 |
| --- | --- | --- | --- |
| 조직 제품 권한 | 조직이 사용할 수 있는 제품 | 네오다임 직원 | 조직별 제품 할당·회수 |
| 조직 역할 | 조직 관리 및 편집 가능 여부 | 오너·네오다임 직원 | 기존 `owner/admin/viewer/staff` 유지 |
| 브랜드 권한 | 사용자가 접근할 수 있는 브랜드 | 조직 오너 | 기존 브랜드 할당 유지 |

제품을 할당받지 않은 조직은 해당 GNB와 하위 메뉴를 숨긴다. 북마크나 직접 URL 접근도 서버에서 `403` 또는 제품 미할당 안내 화면으로 차단해야 한다. 메뉴 숨김만으로 권한 처리를 완료하지 않는다.

네오다임 `staff`는 지원·운영을 위해 모든 조직과 제품에 접근할 수 있도록 예외를 유지한다. 조직 오너는 조직에 할당된 제품만 이용하며, 제품 자체를 할당하거나 회수할 수는 없다.

## 4. 최소 데이터 모델

제품 목록은 우선 코드 상수로 관리하고, 조직과 제품의 관계만 DB에 저장한다.

```text
organization_products
- organization_id
- product_code        // AI_VISIBILITY | SEARCH_CONTENT | YOUTUBE
- status              // active | suspended
- granted_by
- granted_at
- expires_at          // 선택
```

사용자별 제품 할당 테이블은 만들지 않는다. 사용자는 소속 조직의 제품 권한을 상속하고, 기존 역할과 브랜드 권한으로 세부 접근 범위를 제한한다.

## 5. 화면 및 운영안

- GNB의 위치와 명칭은 모든 조직에서 동일하게 유지한다.
- 실제 노출 항목은 현재 조직에 할당된 제품 기준으로 결정한다.
- 홈에서는 할당된 제품 카드와 지표만 표시한다.
- 관리 화면의 조직 상세에 `사용 제품` 영역을 추가한다.
- 제품 할당·회수는 네오다임 직원만 가능하게 한다.
- 제품 회수 시 데이터는 삭제하지 않고 접근만 차단한다.
- 할당 제품이 하나도 없는 조직은 관리 화면만 접근 가능하게 한다.

## 6. 구현 영향 범위

| 영역 | 필요한 변경 |
| --- | --- |
| DB | `organization_products` 추가 |
| 권한 | `canAccessProduct`와 서버/API 공통 가드 추가 |
| 라우팅 | 각 제품에 속한 경로와 `product_code` 매핑 |
| GNB | 현재 조직의 제품 목록에 따른 노출 제어 |
| 홈 | 미할당 제품의 카드·지표·바로가기 제외 |
| 관리 | 조직별 제품 할당 UI 및 감사 로그 추가 |
| 테스트 | 메뉴 숨김, 직접 URL 차단, API 차단, staff 예외 검증 |

## 7. 선결 의사결정

1. 미할당 제품을 GNB에서 완전히 숨길지, 잠금 상태로 노출할지 결정한다. 운영형 B2B 화면에서는 **숨김**을 권장한다.
2. 제품 권한 만료일을 1차 구현에 포함할지 결정한다. 계약 종료 자동 처리가 당장 필요하지 않다면 `expires_at`은 후속 적용한다.
3. 기존 조직의 초기 제품 할당 정책을 정한다. 서비스 중단을 막기 위해 배포 시 기존 조직에는 세 제품을 모두 자동 할당하는 것을 권장한다.

## 8. 단계별 진행안

1. 제품 코드와 화면·API 경로 매핑 확정
2. 조직별 제품 권한 스키마 및 기존 조직 초기값 적용
3. 서버 페이지·API 접근 가드 적용
4. GNB와 홈 노출 제어
5. 조직 관리의 제품 할당 UI 및 감사 로그 적용
6. 역할·브랜드·제품 권한 조합 테스트
