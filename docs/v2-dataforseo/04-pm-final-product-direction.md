# Neodio V2 — DataForSEO 도입 및 GEO 분석 고도화 방향

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.1 |
| 상태 | PM 조건부 승인 피드백 반영 |
| 개정일 | 2026-11-12 |
| 적용 범위 | V2 제품 기획, DataForSEO 전환, 후속 기능 우선순위 |

## 1. 추진 배경

현재 GEO 솔루션 사용자가 겪는 핵심 문제는 다음과 같다.

- 권장된 페이지 최적화를 수행해도 AI 인용률 개선 효과가 명확하지 않다.
- GEO 목적으로 만든 콘텐츠가 실제 AI 답변에 인용되는 비율이 낮다.
- 캠페인을 위해 설계한 프롬프트와 제작 콘텐츠의 연결성이 부족하다.

V2는 DataForSEO 기반 검색·AI 데이터 수집을 도입하고 실제 측정 결과를 중심으로 분석과 개선 기능을 고도화한다.

## 2. 핵심 고도화 방향

| 기능 | 주요 내용 | 기대 효과 |
| --- | --- | --- |
| ① AI 가시성 비교 | Google AI Overview와 AI Mode에서 브랜드 언급·자사 URL 인용·경쟁사 언급·인용 비교 | AI 검색에서 브랜드 경쟁력 파악 |
| ② 프롬프트–콘텐츠 정합성 검증 | 캠페인 목적, 프롬프트, 자사 콘텐츠의 연관성 분석 | 잘못된 프롬프트·콘텐츠 설계 최소화 |
| ③ 경쟁 인용 분석 | AI가 실제 인용하는 경쟁 URL과 반복 인용 도메인 분석 | 콘텐츠 개선 방향의 객관적 근거 확보 |
| ④ 데이터 기반 개선 과제 | AI 답변, 경쟁 인용 출처, 프롬프트, 대상 자사 URL과 콘텐츠 정합성을 연결하고 GSC를 우선순위 보조 근거로 활용 | 일반 체크리스트보다 구체적인 개선안 제공 |
| ⑤ 개선 전후 성과 검증 | 콘텐츠 수정 이력과 동일 조건의 AI 재측정 결과 연결 | 개선 이후 브랜드 언급·인용 변화 확인 |

## 3. 제품 차별화 흐름

```text
프롬프트 전략 수립
→ 콘텐츠 정합성 검증
→ AI 노출·경쟁 인용 분석
→ 개선 과제 도출
→ 재측정 및 성과 검증
```

실제 AI 답변과 경쟁 인용 출처를 개선 근거로 사용하고 후속 결과까지 추적한다. AI 인용 결과는 외부 요인의 영향을 받으므로 효과를 보장하지 않는다. 동일 조건에서 관측된 변화, 개선 가설과 측정 한계를 제시한다.

## 4. 현재 코드 대비 AS-IS / TO-BE

### ① AI 가시성 비교

**이미 있는 메뉴**

- `AI 가시성 > 가시성 개요`
- `브랜드 관리 > 브랜드 가시성`
- `AI 가시성 > 수집 로그`

| 구분 | 내용 |
| --- | --- |
| AS-IS | 모델·마켓별 브랜드 언급, 언급률·자사 인용률, 경쟁 브랜드 Share of Voice와 주간 추세를 제공한다. 수집 로그에서 개별 답변과 인용을 확인할 수 있고 Google AIO·AI Mode 수집 표면도 프롬프트에 지정할 수 있다. |
| 부족한 점 | 동일 프롬프트의 AIO와 AI Mode 결과를 한 행에서 비교하지 않으며, 집계 수치에서 실제 답변으로 이어지는 표면별 비교도 제한적이다. 브랜드 언급과 자사 URL 인용의 관계도 더 명확히 분리해야 한다. |
| TO-BE | `프롬프트 + 위치 + 언어 + 기기 + 수집 시점`을 공통 측정 키로 사용해 AIO와 AI Mode의 브랜드 언급률, 자사 URL 인용률, 경쟁사 언급·인용 현황을 나란히 비교한다. 브랜드 언급과 URL 인용은 독립 지표로 계산하고 표면별 차이와 기간별 변화를 보여준다. Google Organic 결과와 순위는 분석 대상에서 제외한다. |
| 주 적용 메뉴 | `가시성 개요`에 표면 비교를 추가하고, `브랜드 가시성`에는 경쟁사 비교, `수집 로그`에는 근거 원문을 둔다. 신규 최상위 메뉴는 만들지 않는다. |
| 개발 성격 | 기존 집계 화면 재사용 + DataForSEO AIO/AI Mode 정규화 결과 연결 |

### ② 프롬프트–콘텐츠 정합성 검증

**이미 있는 메뉴**

- `프롬프트 관리 > 프롬프트 전략`
- `프롬프트 관리 > 프롬프트 라이브러리`
- `기회 > 개요 및 토픽 상세`
- `도메인 > URL 인스펙터`

| 구분 | 내용 |
| --- | --- |
| AS-IS | 프롬프트 생성 목적·근거를 저장하고, GSC·LLM 브레인스토밍에서 프롬프트 후보를 만든다. 토픽 기회 상세에서 목표 URL을 수동 지정하고 해당 URL의 실제 인용 횟수를 추적한다. 사이트맵 크롤로 FAQ·목차·복잡도·멀티미디어 등 콘텐츠 특성을 진단한다. |
| 부족한 점 | 캠페인 목적, 프롬프트, 목표 URL이 하나의 분석 단위로 연결되지 않는다. 페이지가 질문의 의도와 핵심 하위 주제를 실제로 충족하는지 평가하는 의미적 정합성 분석도 없다. |
| TO-BE | 캠페인 목적 또는 사용자 과업별로 프롬프트 묶음과 목표 URL을 연결한다. 프롬프트 의도, AI 답변의 핵심 주제, 자사 페이지의 제목·본문·FAQ·근거 요소를 비교해 `적합`, `부분 적합`, `콘텐츠 공백`, `대상 URL 부적합`으로 판정하고 근거 문장을 제공한다. |
| 주 적용 메뉴 | `프롬프트 전략`에서 목적과 프롬프트 묶음을 관리하고, `기회 > 토픽 상세`에서 목표 URL 정합성 결과와 개선 항목을 보여준다. `URL 인스펙터`는 페이지 단위 역조회에 사용한다. |
| 개발 성격 | 기존 데이터 기반은 있으나 정합성 판정과 캠페인-프롬프트-URL 연결은 신규 핵심 기능 |

### ③ 경쟁 인용 분석

**이미 있는 메뉴**

- `도메인 > URL 인스펙터`
- `AI 가시성 > 가시성 개요`
- `브랜드 관리 > 브랜드 가시성`
- `AI 가시성 > 수집 로그`

| 구분 | 내용 |
| --- | --- |
| AS-IS | 자사 인용 URL, 제3자 인용 URL, 인용 도메인과 인용 횟수를 집계한다. 경쟁 브랜드의 언급·인용률과 소스 기회도 일부 제공한다. 수집 로그에는 답변 원문과 인용 URL이 남는다. |
| 부족한 점 | 특정 질의에서 자사 대신 어떤 경쟁 URL이 인용됐는지 직접 비교하기 어렵다. 반복 인용 도메인과 경쟁 페이지의 콘텐츠 특성을 개선 근거로 연결하지 않는다. |
| TO-BE | 프롬프트별 자사 도메인·경쟁사 도메인·제3자 출처의 인용 URL, 인용 순서와 답변 문맥을 비교한다. 반복 인용 URL과 프롬프트별 인용 격차를 제시하되 인용 원인을 확정하지 않는다. 콘텐츠 특성의 공통점과 차이는 `관측 사실`, 해석은 `개선 가설`로 표시한다. Organic 위치는 기본 분석에서 제외한다. |
| 주 적용 메뉴 | `URL 인스펙터`를 경쟁 인용 분석의 중심으로 사용하고, `가시성 개요`와 `브랜드 가시성`에는 요약·격차를 제공한다. 원문은 `수집 로그`에서 확인한다. |
| 개발 성격 | 기존 인용 집계 재사용 + 질의 단위 경쟁 비교와 콘텐츠 특성 결합 추가 |

### ④ 데이터 기반 개선 과제

**이미 있는 메뉴**

- `기회 > 개요 및 상세`
- `AI 가시성 > 검색 성과(GSC)`
- `프롬프트 관리 > 프롬프트 전략`
- `도메인 > URL 인스펙터`

| 구분 | 내용 |
| --- | --- |
| AS-IS | 사이트 크롤 결과로 콘텐츠 복구, 복잡도, FAQ, 목차, 구조화 데이터, 멀티미디어 과제를 제시한다. 프롬프트 전략에는 GSC에서 노출되지만 미추적인 쿼리와 노출 대비 클릭이 낮은 URL의 인용 테스트 후보가 있다. 토픽별 목표 URL과 인용 횟수도 관리한다. |
| 부족한 점 | GSC 성과, 실제 AI 답변, 경쟁 인용 URL, 자사 콘텐츠 진단이 서로 다른 화면에 흩어져 있다. 과제 우선순위와 추천 이유가 하나의 근거 묶음으로 고정되지 않는다. |
| TO-BE | `AI 답변 + 경쟁 인용 출처 + 프롬프트 + 대상 자사 URL + 콘텐츠 정합성`을 한 과제에 묶는다. GSC 노출·CTR은 과제 우선순위를 정하는 보조 근거로만 사용한다. 과제에는 관측 사실, 개선 가설, 제안 변경, 우선순위와 재측정 조건을 구분해 기록한다. |
| 주 적용 메뉴 | `기회`를 실행 허브로 사용한다. `검색 성과`, `프롬프트 전략`, `URL 인스펙터`에서는 근거를 발견하고 해당 과제로 이동한다. |
| 개발 성격 | 기존 과제·GSC·인용 기능 통합이 중심이며, 공통 과제 모델과 근거 스냅샷은 신규 |

### ⑤ 개선 전후 성과 검증

**이미 있는 메뉴**

- `기회 > 콘텐츠 복구·FAQ·목차·복잡도·구조화 데이터·멀티미디어`
- `설정 > 변경 이력`
- `브랜드 관리 > 브랜드 가시성`
- `브랜드 관리 > 리포트`
- `AI 가시성 > YouTube 관리`의 작업 이력

| 구분 | 내용 |
| --- | --- |
| AS-IS | 기회 화면은 수정 후 URL을 다시 크롤링해 최초·최신 점수와 기준 통과 여부를 비교한다. 브랜드 언급·인용의 주간 추세, 설정 변경 이력, 확정 리포트 스냅샷, YouTube 최적화 작업 이력이 있다. |
| 부족한 점 | 콘텐츠 변경 행위와 변경 직전 AI 측정 결과가 연결되지 않는다. 변경 후에도 동일 질의·위치·언어·기기·표면으로 재측정했는지 보장하는 기준이 없고, 관측 변화를 해석할 비교군도 없다. |
| TO-BE | 과제 시작 시 변경 전 AI 측정 조건과 결과를 기준선으로 고정하고 콘텐츠 변경일·변경 내용을 기록한다. 동일 프롬프트·위치·언어·기기·표면 조건에서 반복 관측한 후속 수집을 연결해 브랜드 언급과 URL 인용 변화를 독립적으로 보여준다. 결과는 `증가`, `변화 없음`, `감소`, `판정 보류`로 표현하며 관측 변화가 콘텐츠 개선 때문에 발생했다고 단정하지 않는다. |
| 주 적용 메뉴 | `기회 상세`에서 작업과 재측정을 관리하고, `변경 이력`에는 콘텐츠 작업 이벤트를 남긴다. `브랜드 가시성`과 `리포트`에는 전후 결과를 요약한다. |
| 개발 성격 | 자사 크롤 전후 비교는 재사용 가능하나 AI 측정 기준선·변경 연결·후속 판정은 신규 핵심 기능 |

### 메뉴 구성 원칙

①~⑤를 위해 새로운 최상위 메뉴를 다섯 개 만들 필요는 없다. 기존 메뉴 역할을 다음처럼 정리한다.

```text
프롬프트 전략·라이브러리  → 무엇을 측정하고 어떤 콘텐츠와 연결할지 결정
가시성 개요·브랜드 가시성 → AI 노출과 경쟁 격차 확인
URL 인스펙터              → 자사·경쟁 인용 근거 분석
기회                       → 개선 과제 실행과 재측정 관리
수집 로그                  → 원문·Task·비용 감사
리포트                     → 확정된 결과와 전후 변화 공유
```

### 공통 구현 경계

- 기존 최상위 메뉴를 추가하지 않는다.
- 기존 기능, 수집 이력, 화면과 API 계약의 하위 호환성을 유지한다.
- 신규 DB 구조와 세부 구현 범위는 별도 설계 문서와 승인을 거친다.
- DataForSEO Stage A/B 전환과 ①~⑤ 인사이트 고도화 개발은 별도 작업 트랙과 승인 게이트로 운영한다.
- 현재 개정 범위는 기획 문서에 한정하며 코드와 DB를 변경하지 않는다.
- AIO 수집에 Google Organic Advanced 엔드포인트를 사용하더라도 일반 Organic 결과와 순위는 제품 분석에 사용하지 않는다.

## 5. 개발 및 도입 단계

### 트랙 A — DataForSEO 검증 및 전환

- Google AI Overview·AI Mode의 한국어 답변 및 인용 데이터 검증
- 기존 브라우저 기반 수집의 API 기반 점진 전환
- 기존 메뉴와 핵심 기능 유지

Stage A/B의 통과 여부와 운영 전환 승인은 이 트랙에서 독립적으로 관리한다.

### 트랙 B — 핵심 GEO 인사이트 고도화

- 표면별 브랜드 가시성 비교
- 프롬프트–콘텐츠 정합성 분석
- 경쟁사 인용 분석
- 실제 데이터를 활용한 개선 과제 추천

트랙 B는 별도 기능 설계와 승인을 받은 뒤 시작하며 Stage B 완료가 자동 개발 승인을 의미하지 않는다.

### 후속 확장

- GSC를 보조 우선순위로 활용하는 AI 관측 교차 분석
- 콘텐츠 개선 전후 관측 변화 추적
- 필요에 따른 검색량, 트렌드, YouTube, 백링크 데이터 확장

신규 데이터 제품군은 한국어 지원 범위와 실제 비용을 검증한 뒤 단계적으로 도입한다.

## 6. 기대 효과와 최종 목표

- 고객은 GEO 개선 작업의 근거와 관측된 성과를 더 명확히 확인한다.
- 운영자는 반복적인 수동 수집 부담을 줄이고 경쟁 현황을 정기적으로 분석한다.
- 제품은 단순 모니터링에서 콘텐츠 개선 의사결정 지원으로 확장한다.

최종 목표는 AI 인용률만 보여주는 도구가 아니라 **어떤 콘텐츠를 왜 개선해야 하며 실제로 어떤 변화가 있었는지 설명할 수 있는 GEO 운영 플랫폼**을 구축하는 것이다.
