# 클라이언트 보고용 리포트 설계

대시보드 데이터를 클라이언트에게 보고할 수 있는 보고서 화면과 PDF 내보내기. 구현 전이다.

## 확정된 결정 (2026-10)

- **표지는 없다.** 첫 쪽부터 요약으로 시작한다.
- 부록은 점수 정의·관측 수·표본 수만 담지 않는다 — 그것만 있으면 전문성이 부족해 보인다. 아래 "부록 구성"의 항목으로 채운다.

## 본문 구성

1. **요약**: 가시성 점수, 언급률, 인용률(직전 기간 대비), 핵심 인사이트 3줄(자동 초안 + 담당자 편집)
2. **추이**: 주별 가시성·언급률, 설정 버전 표시선(변경 이력과 연결)
3. **엔진별 현황**: 엔진별 언급률, 노출 위치, 엔진×질의 히트맵
4. **경쟁사 비교**: 마켓 비교, 쉐어 오브 보이스
5. **잘되는 점·놓치는 점**: 상위 프롬프트, 토픽 기회
6. **출처·인용**: 인용된 소스, 경쟁사만 혜택을 보는 소스
7. **실행 제안**: 기회 항목과 다음 기간 계획(담당자 코멘트)

## 부록 구성

| 항목 | 내용 |
|---|---|
| 측정 개요 | 측정 기간, 대상 AI 엔진, 마켓, 수집한 프롬프트·답변 수 |
| 지표 정의 | 가시성 점수(언급·인용·노출 위치 가중), 언급률, 인용률, 노출 위치의 정의를 그림과 함께 |
| 데이터 품질 | 엔진별 수집 성공률, AI 미답변 비율, 같은 질의 반복 수집 현황, 관측 수와 표본 수 |
| 질의 구성 | 브랜드 질의와 일반 질의 비율, 카테고리·토픽별 프롬프트 수 |
| 비교 대상 | 경쟁사·기타 브랜드 목록과 별칭 기준 |
| 설정 이력 | 보고 기간 중 프롬프트·브랜드 설정 변경(변경 이력에서 가져옴), 사용한 설정 버전 |
| 해석 가이드 | 숫자를 읽는 법(AI 답변은 매번 달라짐, 표본이 적을 때 주의, 감성은 참고용) |
| 용어 설명 | 인용, 관측, 쉐어 오브 보이스, AI 미답변 등 |

## 보고서는 스냅샷으로 저장

생성 시점의 값을 고정해야 나중에 별칭을 바꾸거나 수집이 늘어도 이미 보낸 보고서 숫자가 달라지지 않는다.
수정하려면 새 버전을 만든다.

```sql
reports (id, organization_id, brand_id, title, period_start, period_end,
         filters_json,              -- 마켓·모델·질의 유형
         config_version_id,         -- 보고 시점의 설정 버전(config_versions)
         snapshot_json,             -- 생성 시점의 지표 값 전체
         status,                    -- draft | final
         created_by, created_at, finalized_at)
report_sections (report_id, key, included BOOLEAN, commentary TEXT, position INT)
report_shares (id, report_id, token_hash, expires_at, created_by, revoked_at)
```

접근: 리포트 열람은 `viewer` 이상. 생성·편집은 해당 브랜드의 `admin`과 오너. 공유 링크(읽기 전용, 만료 있음)는 오너와 해당 브랜드 admin이 만든다.

## PDF

| 단계 | 방식 |
|---|---|
| 1 | A4 인쇄용 CSS 페이지(페이지 나눔 제어) + 브라우저 "PDF로 저장". 차트가 SVG(recharts)라 선명하다. |
| 2 | 서버에서 헤드리스 Chromium으로 생성(`/api/reports/[id]/pdf`) |
| 3 | 월간 자동 생성·이메일 발송, 공유 링크 |
