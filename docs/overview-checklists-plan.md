# 개요 체크리스트 2종 — 실제 데이터/텍스트/링크로 전환 기획

> 대상: 개요(`/`) 화면의 "더 많은 인사이트를 확인하는 다음 단계"(6단계), "프롬프트 전략 강화하기"(5단계) 카드.
> 현재 상태: [src/lib/db/data/overview.ts](../src/lib/db/data/overview.ts)의 `checklistByOrg`에 원본 Figma 템플릿 문구가 그대로 하드코딩돼 있고, `done` 플래그도 고정값. [ChecklistCard.tsx](../src/components/overview/ChecklistCard.tsx)는 각 단계에 클릭 액션이나 링크가 전혀 없음(화살표 아이콘만 장식용).

## 원칙

각 단계를 아래 세 그룹 중 하나로 분류한다.

- **A. 실 데이터/링크로 전환 가능** — 이미 이 프로젝트에 해당 기능이 구현돼 있어, 완료 여부를 실제 상태에서 계산하고 실제 페이지로 링크만 걸면 됨.
- **B. 부분 전환** — 관련 데이터 필드(`cdnConnected` 등)는 있지만 그 기능 자체(연동 화면, 실제 파이프라인)가 아직 없음. 완료 여부는 실 데이터로 계산 가능하나, 클릭했을 때 갈 곳이 없음.
- **C. 이 제품과 안 맞음 — 삭제 권장** — 원본 템플릿이 다른 종류의 제품(엣지 사전 렌더링/CDN 봇 최적화 SaaS)을 가정한 문구라 이 프로젝트 범위에 없고 앞으로도 만들 계획이 없음.

## 체크리스트 1: "더 많은 인사이트를 확인하는 다음 단계"

| # | 현재 문구 | 분류 | 처리 방안 |
|---|---|---|---|
| 1 | 가입 완료 | A | 그대로 유지, `done: true` 고정 (로그인된 시점에서 항상 참) |
| 2 | 어떤 AI 엔진이 나를 인용하는지 확인하기 | **A** | "수집 로그"가 정확히 이 기능. 문구를 "네이버·구글 AI 답변 수집 시작하기"로 구체화하고 `/collection-runs`로 링크. 완료 여부 = 실제 수집된 인용(citation) 1건 이상 존재 |
| 3 | 원클릭 배포 활성화하기 | **C** | "개발팀 없이 AI 봇용 최적화 배포"는 엣지/프리렌더링 인프라가 필요한 기능 — 이 프로젝트 범위 밖. **삭제 권장** |
| 4 | 더 많은 AI 검색 노출 확보하기 | **A** | 프롬프트 라이브러리에 프롬프트 추가하는 것과 동일한 행동. `/prompt-library`로 링크, 완료 여부 = 라이브러리에 프롬프트 1건 이상 존재(항상 참에 가까움 — 문구를 "새 프롬프트 추가하기"로 좁히거나 이 항목 자체를 4번 체크리스트의 "프롬프트 직접 업로드하기"와 통합 검토) |
| 5 | 시장 기회 발견하기 | **A** | `/opportunities`로 링크. 완료 여부 = 해당 페이지 열람 이력을 추적할 방법이 없으니, 기회 데이터가 1건 이상 존재하는지로 대체하거나 done 플래그 없이 액션 링크로만 유지 |
| 6 | 게시하고 노출되기 (사전 렌더링) | **C** | 설명 자체가 "이 사이트엔 사용 가능한 사전 렌더링 기회가 없습니다"로 이미 기능 부재를 인정하는 문구. **삭제 권장** |

→ 6단계 중 2단계(3, 6) 삭제 시 **4단계**로 축소. 나머지는 실 링크/완료 조건 부여 가능.

## 체크리스트 2: "프롬프트 전략 강화하기"

| # | 현재 문구 | 분류 | 처리 방안 |
|---|---|---|---|
| 1 | AI 트래픽 분석을 위해 CDN 연동하기 | **B** | `BrandsManagementBrand.cdnConnected` 필드는 있지만 CDN 연동 화면 자체가 없음(P0 제외, neodigm_p0_scope.md). 완료 여부는 실 데이터(`cdnConnected`)로 계산 가능하나 클릭 시 갈 곳이 없어 지금은 "준비 중" 배지 처리하거나 항목 유지만 하고 링크 비활성화 |
| 2 | 쿼리 분석을 위해 GSC 연동하기 | **A** | 이미 완전히 구현됨(Manage Connections GSC 탭). `/brands-management/[brandId]/connections`로 링크, 완료 여부 = `GscConnection.status === "connected"` (Neodigm은 이미 연결됨 → done:true로 바뀜) |
| 3 | 리퍼럴 트래픽을 위해 웹 분석(GA4) 연동하기 | **B** | `analyticsConnected` 필드는 있지만 GSC처럼 실제 연동 화면(OAuth 등)이 없음. CDN과 동일하게 "준비 중" 처리 |
| 4 | 프롬프트 직접 업로드하기 | **A** | 프롬프트 라이브러리의 "CSV 가져오기"/"프롬프트 추가" 기능과 정확히 일치. `/prompt-library`로 링크, 완료 여부 = manual/csv_import 출처 프롬프트 1건 이상 존재 (지금 mock 데이터 기준 이미 참) |
| 5 | 라이브러리에 프롬프트 제안 추가하기 | **B** | "AI가 생성한 프롬프트 제안"은 지난 대화에서 논의된 LLM 기반 프롬프트 생성 기능 — API 키 미설정으로 아직 미구현. 구현 전까지는 "준비 중" 처리 |

→ 5단계 중 실전환 가능은 2개(2, 4), 나머지 3개는 실제 연동 화면/LLM 기능이 먼저 필요해 "B(부분 전환)"로 표시.

## 구현 방향 제안

1. `ChecklistItem`/`ChecklistStep` 타입에 `href?: string`(실제 이동 경로)와 `available: boolean`(클릭 가능 여부 — B/C 항목은 false) 필드 추가
2. `ChecklistCard.tsx`에서 `available === false`인 단계는 화살표 대신 "준비 중" 배지를 표시하고 클릭 비활성화, `available === true`면 `href`로 실제 이동
3. `done` 값을 하드코딩이 아니라 실제 상태(수집 실행 존재 여부, GSC 연결 상태, 프롬프트 라이브러리 항목 존재 여부)에서 계산하도록 `checklistByOrg`를 함수화 (`getChecklist(orgId)`가 이미 async라 실 계산 넣기 용이함)
4. C로 분류된 2개 항목(원클릭 배포, 사전 렌더링) 삭제 — 체크리스트 1은 6단계 → 4단계로, 총 단계 수(`totalSteps`)도 함께 조정

## 열린 질문

- B로 분류된 항목(CDN/Analytics 연동, AI 프롬프트 제안)을 화면에 "준비 중"으로 남겨둘지, 아예 체크리스트에서 빼서 실제로 할 수 있는 항목만 보여줄지 — 데모 임팩트(더 풍부해 보임) vs 정직성(누르면 아무것도 안 됨) 트레이드오프
- 체크리스트 1의 4번("더 많은 AI 검색 노출")과 체크리스트 2의 4번("프롬프트 직접 업로드")이 사실상 같은 행동(프롬프트 라이브러리에 추가)이라 두 체크리스트에 걸쳐 중복됨 — 통합할지 그대로 둘지
