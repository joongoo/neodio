# DataForSEO 수집 기능 업데이트

> 적용 예정일: 2026-11-18

프롬프트 라이브러리에서 Google AIO, Google AI Mode, Naver AIO 검색 결과를 SERP API로 수집할 수 있습니다.

## 달라진 점

- 수집을 시작하기 전에 예상 요청 수와 비용을 확인할 수 있습니다.
- 수집 중인 항목은 프롬프트 라이브러리와 수집 로그에서 확인할 수 있습니다.
- 페이지를 이동했다가 돌아와도 진행 중인 수집 내역이 다시 표시됩니다.
- 아직 API에 제출되지 않은 작업은 `수집 대기`로 표시되며, 직접 제출하거나 삭제할 수 있습니다.
- 이미 같은 프롬프트를 수집 중이라면 해당 작업의 시작 시각과 검색 엔진을 안내합니다. 그래도 다시 수집할 때만 확인 후 중복 수집을 진행합니다.
- 여러 프롬프트를 한 번에 선택해 대량으로 수집할 수 있습니다.

## 알아두세요

- API에 제출된 수집은 페이지를 떠나도 계속 진행됩니다. 다만 현재는 별도 서버 worker가 없으므로, 페이지를 떠난 동안 완료된 결과는 프롬프트 라이브러리나 수집 로그 페이지에 다시 진입했을 때 반영됩니다. 따라서 수집 중에는 페이지를 이탈하지 않는 것을 권장드립니다.
- 대량 수집은 모든 작업이 API에 제출(수집 시작)될 때까지 해당 페이지를 유지하는 것이 안전합니다.
- SERP API 수집은 실제 API 비용이 발생합니다.
  - Google AIO: 건당 $0.0024
  - Google AI Mode: 건당 $0.0012
  - 네이버 AIO: 건당 $0.0006

## 작업 큐 전환 변경 기록

### 2026-11-19 — 수집 요청 필터와 확인 완료

- 수집 로그의 상태·플랫폼은 여러 개 선택할 수 있으며, 조회 버튼 없이 결과가 바뀝니다. 같은 필터 안에서는 OR, 필터 간에는 AND로 적용하며 키워드 검색은 제거했습니다.
- ‘확인 필요’는 실행 상태와 분리했습니다. 상단 카드를 누르면 ‘확인 필요만 보기’ 스위치도 켜집니다.
- 요청마다 ‘확인 완료’를 눌러 더 조치하지 않을 요청을 정리할 수 있습니다. 실패 이력은 유지하고, 확인 필요 목록·카드·사이드바 느낌표에서 제외합니다. 같은 요청에 새로운 제출 실패가 발생하면 다시 표시합니다.
- 목록에 자동 폴링은 추가하지 않았습니다. 확인 완료는 재수집이나 유료 API 제출을 발생시키지 않습니다.


### 2026-11-19 — 사이드바 수집 상태 격리와 아이콘 표시

- 수집 로그 메뉴의 숫자 배지를 제거하고, 진행 중이면 파란 스피너, 확인할 항목이 있으면 주황 느낌표로 표시합니다. 두 상태가 함께 있으면 두 아이콘을 표시합니다.
- 상태 조회는 메뉴·본문 렌더링과 분리했습니다. 조회 실패 또는 2초 초과 시 회색 물음표로 ‘수집 상태 확인 불가’를 안내하며, 다른 메뉴 이용은 계속할 수 있습니다.
- 사이드바는 건수 대신 해당 상태의 존재 여부만 조회합니다. 기존 진입 시 1회 조회 정책을 유지하고 자동 폴링·재시도·외부 API 호출을 추가하지 않았습니다. 수집 로그 본문의 건수 집계는 유지합니다.

### 2026-11-18 — 제출 실패만 재수집 / 상세 상태 문구 통일

- 분석 실패는 일반 재수집 대상과 ‘확인 필요’ 집계에서 제외했습니다. 실패 항목 중 제출 실패만 재수집 가능하며, 취소·미실행 대기 조작은 유지합니다. 분석 실패 이력과 실패 합계는 그대로 확인할 수 있습니다.
- 테이블 상태를 필터와 같은 세부 문구로 표시합니다. ‘실패’ 대신 ‘제출 실패·분석 실패’, ‘확인 필요’ 대신 ‘제출 확인 필요’ 등 실제 항목 상태를 구분합니다.
- 개별 선택·전체 선택·선택 가능 건수와 서버 재요청 검증에 같은 정책을 적용했습니다. 확인 필요 카드도 제출 실패·제출 여부 불명확만 대상으로 안내합니다.

### 2026-11-18 — 수집기 미연결은 대기로 유지

- 수집기를 찾지 못하거나 버전·Chrome 문제로 시작하지 못한 로컬 수집은 취소가 아닌 대기로 표시합니다. 안내창을 닫거나 페이지를 떠나도 시작 전 항목은 대기를 유지합니다.
- 실제 수집 중이던 항목의 이탈 중단과 사용자의 명시적인 취소는 기존 취소 처리로 유지합니다. 이미 기록된 과거 취소 상태를 자동 변경하지 않습니다.

### 2026-11-18 — 실제 비용을 진행 현황 카드로 이동

- 수집 요청 최상단의 예상/실제 비용 문구를 제거하고, 수집 진행 현황에 ‘실제 발생 예상 비용’ 카드 하나를 추가했습니다. 예상 비용은 표시하지 않고 실제 비용 집계값만 USD로 표시하며 0원은 `-`로 표시합니다.

### 2026-11-18 — SERP Google AIO 인용 판정 호환

- SERP로 수집한 Google AIO에도 기존 수집기와 동일한 자사 채널·자사 웹·경쟁사 판정을 적용합니다. 자사 영상은 채널 ID로 판정하며 영상 제목·채널·재생 시점도 유지합니다.
- 판정 결과를 AIO 대시보드와 공통 수집 결과에 함께 반영합니다. 영상 정보는 기존과 같은 캐시 우선 조회를 사용하며 확인하지 못한 영상은 자사로 단정하지 않습니다.
- 이번 변경은 이후 저장·재처리되는 결과에 적용되며, 이미 완료된 과거 결과를 자동 재수집하거나 소급 수정하지 않습니다.

### 2026-11-18 — PostgreSQL 선점·취소 경합 검증

- 실제 로컬 PostgreSQL의 독립 연결 두 개로 worker 동시 선점 상한, 선점과 취소가 겹치는 두 경우, 임대 만료 후 이전 worker의 제출 차단을 검증했습니다.
- worker가 먼저 선점한 경우 일괄 취소는 부분 처리 없이 거부하며, 취소가 먼저 완료되면 worker는 작업을 제출하지 않습니다. 취소 이력은 보존합니다.
- 테스트는 격리된 임시 스키마에서만 실행하며 기존 데이터와 외부 API를 사용하지 않습니다. 예산 제한 기능은 사용자 요청으로 당장 진행할 범위에서 제외했습니다.

### 2026-11-18 — 중단·중복 실행 안전성 회귀 검증

- worker가 제출 전에 중단되면 임대 만료 후 같은 예약을 이어받고, 이전 worker는 제출할 수 없는지 검증했습니다.
- 제출 응답이 유실된 경우 자동으로 다시 과금하지 않고 ‘제출 확인 필요’로 남기는 것과, 중복 실행 알림이 같은 작업을 두 번 제출하지 않는 것을 검증했습니다.
- 결과 회수가 중단되면 기존 외부 작업을 이어서 회수하고 새 제출을 만들지 않는지 검증했습니다. 이번 작업은 모의 상태 기반 테스트 보강이며 실제 프로세스·Vercel 배포 검증은 별도로 남아 있습니다.

### 2026-11-18 — 이전 개별 이력의 직접 조작 종료

- 이전 개별 이력의 ‘지금 제출·예약 삭제’를 제거하고 연결된 수집 요청 상세로 안내합니다. 실행은 비용 확인 후 기존 큐 순서·동시 실행 제한을 따르며 취소 시 이력은 보존됩니다.
- 예전 직접 제출·삭제 API도 종료해 오래 열린 화면에서 안전 정책을 우회할 수 없도록 했습니다. 요청에 연결되지 않은 과거 예약은 읽기 전용으로 유지하며, 새 수집이 필요하면 라이브러리에서 별도 승인하도록 안내합니다.

### 2026-11-18 — 요청 상세 상단 요약 정리

- 최상단 카드에서 중복되는 전체·완료 등 항목별 건수와 수집 채널 목록을 제거했습니다. 요청 상태·등록 시각·요청자·예상/실제 비용은 유지하며, 단계별 건수는 아래 수집 진행 현황에서 확인할 수 있습니다.

### 2026-11-18 — 다중 필터 클릭 영역과 열린 상태 유지

- 상태·플랫폼 옵션은 체크 표시뿐 아니라 이름·건수·여백을 포함한 행 전체를 클릭할 수 있습니다.
- 항목 선택 후에도 드롭다운을 유지해 연속 선택할 수 있습니다. 조회 중에는 중복 선택을 막되 포커스를 유지합니다. 외부 클릭·포커스 이탈·Esc 닫기는 유지합니다.
- 상태·플랫폼·정렬 버튼 우측 아이콘을 동일한 아래쪽 화살표로 통일했습니다.

### 2026-11-18 — 필터 기반 전체 선택으로 단순화

- 실패·취소 전용 전체 선택 버튼을 없애고, 현재 필터에 맞는 모든 페이지의 선택 가능한 항목을 고르는 ‘전체 선택’으로 통합했습니다. 필터는 자동으로 바꾸지 않습니다.
- 이미 재수집한 원본·완료·제출 확인 필요·선점된 SERP 대기 작업은 전체 선택에서 제외합니다. 선택 가능한 항목이 없으면 버튼을 비활성화합니다.
- 필터 변경 시 렌더 도중 상태를 재설정하던 경로를 제거하고, 드롭다운은 React 상태로 열고 닫도록 변경했습니다. 필터를 직접 변경하면 선택은 초기화하고 페이지·정렬 변경 시에는 유지합니다.

### 2026-11-18 — 전체 선택과 상태 필터 연동

- 실패·취소 항목 전체 선택에 성공하면 선택된 항목에 해당하는 상태를 필터에도 체크합니다. 기존 선택과 다른 필터는 유지하며, 선택 해제만으로 상태 필터를 되돌리지는 않습니다.
- 상태·플랫폼·정렬 드롭다운은 다른 곳을 클릭하거나 키보드 포커스가 밖으로 나가면 닫힙니다. Esc로도 닫을 수 있습니다.

### 2026-11-18 — 상세 다중 필터와 선택 가능 건수

- 수집 요청 상세에서 상태와 플랫폼을 여러 개 선택할 수 있습니다. 같은 필터 안에서는 하나라도 일치하면 표시하고, 상태와 플랫폼 조건은 함께 적용합니다.
- 필터별 결과 건수를 표시하고 결과가 없는 옵션은 흐리게 비활성화합니다. 이미 선택한 옵션은 0건이어도 해제할 수 있습니다.
- 실패·취소 전체 선택 버튼에 현재 필터 내 재수집 가능한 건수를 표시하며, 0건이면 클릭할 수 없습니다. 이미 재수집한 원본은 제외합니다. 추가 HTTP 요청 없이 기존 현황 조회에서 함께 집계합니다.

### 2026-11-18

- 로그 상세 필터를 프롬프트 라이브러리와 같은 드롭다운 UI로 바꾸고, 조회 버튼 없이 변경 즉시 목록을 갱신하도록 했습니다. 필터·검색·페이지 이동은 페이지 전체를 다시 불러오지 않는 CSR 방식이며 URL과 뒤로 가기 상태를 유지합니다.
- 실패·취소 전체 선택은 현재 검색어·상태·플랫폼·기간 조건에 맞는 모든 페이지의 항목에만 적용됩니다. 필터 변경 시 기존 선택을 초기화해 숨겨진 항목의 의도하지 않은 재수집을 방지합니다. 이미 재수집된 원본 제외와 비용 확인은 유지합니다.
- 요청 상세에서 미제출 SERP 대기 항목을 선택해 실행 확인을 요청하거나 일괄 취소할 수 있습니다. 실행은 새 요청·task를 생성하지 않고 기존 큐 worker에 알리며, 처리 순서·동시 실행 제한을 유지합니다. 실행 전 기존 예약의 예상 비용을 확인합니다.
- 대기 취소는 항목을 삭제하지 않고 취소 이력을 남깁니다. 이미 제출되었거나 worker가 선점한 항목은 조작하지 않으며, 선택 중 상태가 바뀌면 전체 조작을 거부합니다. 실패 재수집·로컬 수집과 대기 SERP 조작은 별도로 선택하도록 구분합니다.
- 실패·취소 항목을 각각 전체 선택하는 토글 버튼과 ‘전체 선택 해제’를 추가했습니다. 두 그룹은 누적 선택되며 버튼 색상으로 선택 상태를 구분하고, 같은 버튼을 다시 누르면 해당 그룹만 해제합니다.
- 필터 조회 시 ‘전체 상태/전체 엔진’의 빈 쿼리 값 때문에 결과가 사라지던 문제를 수정했습니다. 목록·상세·현황 API가 빈 필터를 동일하게 해석하도록 검증했습니다.
- 이미 재수집이 등록된 원본 항목은 개별·전체 선택에서 제외하고 서버에서도 재제출을 차단합니다. 후속 요청이 완료·실패·취소돼도 원본은 다시 선택할 수 없으며, 추가 재수집은 실패한 최신 요청에서 진행합니다.

- 프롬프트 라이브러리에 다시 들어와도 진행 중인 SERP API 작업 때문에 진행 모달이 자동으로 열리지 않도록 변경했습니다.
- SERP API만 수집할 때는 작업 큐 등록 결과와 수집 로그 이동만 안내하고, 레거시 수집을 함께 실행할 때는 기존 진행 화면을 유지하도록 정리했습니다.
- 혼합 수집 화면에서 SERP API는 진행률 패널 대신 서버 작업 큐 등록 상태로 구분해 표시합니다.
- 한 번의 사용자 승인에서 나뉘어 들어오는 엔진·배치 요청을 하나의 수집 요청으로 식별할 수 있도록 실행 ID 저장 기반을 추가했습니다.
- 프롬프트 라이브러리의 실제 예약 API가 같은 실행 ID의 수집 요청을 재사용하고, 새로 만든 Provider 작업만 건수와 예상 비용에 누적하도록 연결했습니다.
- 이미 진행 중인 작업을 재사용하거나 같은 예약 요청이 다시 도착해도 수집 요청 비용이 중복 집계되지 않도록 처리했습니다.
- 예약 작업이 생기면 Vercel Queue가 worker를 깨우고, 처리할 작업이 남은 동안에만 지연 메시지로 후속 실행하도록 이벤트 기반 실행 경로를 추가했습니다.
- 큐 메시지 발행은 실행 플래그로 분리했으며, 작업 ID 기반 중복 방지 키로 같은 예약 요청이 다시 도착해도 불필요한 worker 호출을 줄였습니다.
- Provider 제출 도중 서버가 종료되어 오래 `submitting`에 머문 작업은 자동 재제출하지 않고 `확인 필요` 상태로 격리하는 stale-task sweeper를 추가했습니다.
- 최근 제출이거나 기존 worker lease가 살아 있는 작업은 sweeper가 건드리지 않도록 보호했습니다.
- 요청 묶음과 각 수집 작업을 연결하고, 서버가 중단된 작업을 이어받을 수 있도록 필요한 기록 항목을 준비했습니다.
- 이용량이 늘어도 화면 서버 전체가 아니라 수집 처리 부분만 확장할 수 있도록 실행 영역의 분리 기준을 정했습니다.
- 이후 화면을 닫아도 서버가 남은 제출과 결과 반영을 이어가고, 수집 로그에서 요청 전체의 진행 상황을 확인할 수 있도록 단계적으로 적용합니다.
