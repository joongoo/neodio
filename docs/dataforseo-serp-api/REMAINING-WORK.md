# 남은 작업과 우선순위

> 최종 갱신: 2026-11-20
> 미완료 작업과 유지할 기준만 기록한다. 완료한 항목은 삭제하고 작업 로그·커밋·테스트 통과 이력은 쌓지 않는다.

## 최우선 — Gemini 인용 화면 검증

- 스테이징 브라우저에서 `Gemini 인용`의 기간 선택·검색·인용 필터·프롬프트/영상 페이지 이동·답변 상세·출처 링크·빈 상태·일별 차트를 검증한다.
- 브랜드 수집 요청에 연결된 Gemini API 결과만 표시한다. 요청 연결이 없는 과거 결과는 수집 로그에서 확인한다. 프롬프트 유사성이나 현재 추적 관계로 브랜드 소유권을 추정하지 않는다.
- 지표는 기간 내 프롬프트별 최신 수집 기준이다. 실패·웹 검색 미사용·검색 여부 미기록은 분모에서 제외한다. 자사 인용률은 채널 판별 가능 답변 기준이며 채널 미확인은 별도로 표시한다. 영상 메타는 기존 DB 캐시만 읽는다.
- 신규 수집 방식·영상 메타 보강·과거 데이터 연결은 별도 범위 결정이 필요하다.

## 후순위 — 수집 전환 검증과 운영 점검

- 로컬 mock worker의 실제 강제 종료·재시작, 네트워크 단절 후 복구와 중복 제출 방지를 E2E로 검증한다.
- Vercel Preview의 인증·큐 전달·중복 전달·지연 실행을 검증한다.
- 스테이징 브라우저에서 목록 다중 필터·뒤로가기·확인 필요 카드와 스위치 동기화, 확인 완료 후 사이드바 갱신과 이력 보존을 확인한다.
- 실제 브라우저·설치형 수집기의 취소 신호 수신과 종료 응답을 확인한다.
- 브라우저 강제 종료 후 로컬 수집 미반영 상태의 정합성 복구를 점검한다.
- stale 경보·운영 상태 표시, 실행 계층 DB 초기화, artifact adapter 설정을 점검한다.
- 사이드바 상태 조회의 UI 대기 상한과 별개로, 실행 중인 DB 읽기의 timeout·연결 자원 제한을 점검한다.
- 실행 상한 30건 적용 시 운영의 `DATAFORSEO_MAX_IN_FLIGHT`·`DATAFORSEO_SUBMIT_BATCH_SIZE`에 더 작은 값이 남아 있는지 확인한다. worker 재시작·새 배포 적용도 확인한다.

## 후속 계획과 보류

- ‘확인 필요 0건’ 초록 상태 카드: 합의된 계획, 미구현.
- 분석 실패 원본 재처리: 일반 유료 재수집과 별도 기능으로 검토한다.
- 로컬 수집 항목별 실제 실행 수: 필요 시 수집기의 항목별 시작 이벤트 연동을 검토한다.
- 결과 반영 단계 통합 표시: 제안 단계다. 제출 실패·분석 실패·제출 확인 필요는 조치가 달라 구분을 유지한다.
- 과거 관측의 인용 판정 소급 보정, 요청 미연결 과거 예약 정리: 별도 범위 결정이 필요하다. 자동 보정·병합하지 않는다.
- 수만 건 이상 선택·등록: 필요 시 서버 선택 토큰·청크 등록을 검토한다.
- 조직별 예산 제한·최종 수집일 기능: 보류.

## 유지할 기준

- 유료 task 자동 재제출 금지. `submission_unknown`은 확인 필요로 유지하며 최초 요청을 자동 재POST하지 않는다. 실제 유료 검증은 사용자의 명시적인 실행 요청 범위에서 수행한다.
- 실패 항목의 일반 재수집은 `provider_failed`만 허용한다. `parse_failed`는 원본 재처리 대상으로 구분한다.
- 요청 상세의 자동 갱신은 활성 항목이 있을 때 내부 DB를 5초 간격으로 읽는다. 외부 Provider API 직접 조회나 작업 제출을 유발하지 않는다. 목록·사이드바·라이브러리로 자동 polling을 확장하지 않는다.
- 취소는 이력을 보존한다. 이미 제출된 작업의 결과 회수는 유지하며 미제출 작업 취소와 유료 신규 재수집을 구분한다.
- 요청 연결 정보가 없는 과거 이력 접근을 유지하고, 시간·프롬프트 유사성만으로 요청을 임의 병합하지 않는다.
- 로컬 mock·DB 테스트와 실제 Provider·브라우저·Vercel 검증을 구분한다.
- 브랜치·PR·출시는 [릴리스 운영 지침](../operations/release-guide.md)을 따른다.
