# GEO 경쟁 제품 리서치 로그

목적: 경쟁/유사 제품 자료를 계속 모아두고, 다 모인 뒤 한 번에 정리해서
기획 → 작업 순서로 진행한다. 지금 단계에서는 **분석만 쌓아두고 코드/앱
콘텐츠(help.ts 등)에는 반영하지 않는다.**

각 항목: 원문 출처 요약 → 우리 제품과 비교했을 때 눈에 띄는 점 → 반영
여부 판단(반영 검토/이미 있음/방향 다름)은 전체 리서치가 끝난 뒤 마지막에
한 번에 정리한다. 지금은 "관찰"만 기록.

## 2026-09-23 — VIVI (Content Assistant + Insight/Action)

### 원문 요약
- **VIVI Content Assistant**: 크롬 사이드패널 확장 프로그램. 지금 보고
  있는 페이지를 9개 모듈(AI 크롤러 접근성, 구조화 데이터, 메타데이터,
  인용 신뢰도 등)로 진단, 100점 환산 점수 제공. CMS 편집 화면에서는
  JSON-LD·메타데이터·FAQ를 바로 삽입 가능한 형태로 생성. 자체 포함 HTML
  리포트로 공유, 최근 진단 40개 이력 보관.
- **VIVI Insight**: 국내외 AI 엔진 6개(Naver AI Briefing, Google AI
  Overview, AI Mode, Gemini, Perplexity, ChatGPT — Claude/Bing/Yahoo는
  지원 예정)에서 동일 질문의 답변을 수집. Mention Rate·Citation
  Rate·Share of Voice·Visibility Funnel(단계별 이탈) 4개 지표로 측정.
  플랜별로 엔진/프롬프트 수 다르고, 브랜드 아래 프로젝트 단위로 구분.
- **VIVI Action**: Insight가 찾은 약점에 대응하는 콘텐츠 생성/개선 실행.
  취약 토픽 → 콘텐츠 생성, 통이미지 상세페이지 → AI가 읽는 텍스트(PDP
  변환)로 전환. 실행 후 같은 지표로 재측정.
- 사용 흐름: Setup(최초 1회) → Metrics → Topics → Topic Research →
  Pages, 이후 매주 같은 순서로 반복.

### 관찰 (우리 제품과 비교)
- **없는 개념**: 구조화 데이터(JSON-LD) 진단/생성이 별도 기회 유형으로
  없음. 언급→인용 단계별 퍼널 뷰가 없음(우리는 독립된 숫자만). 수집
  엔진이 네이버 AI검색·구글 AI Overview 2개뿐(Perplexity/ChatGPT/Gemini
  없음).
- **개념은 있는데 형태가 다름**: Share of Voice ≈ 우리 브랜드 가시성의
  마켓 트래킹 비교. PDP 변환 ≈ 우리 멀티미디어 가시성 보강. 진단 이력
  40개 ≈ 우리 토픽 상세의 "수집 로그별 변화".
- **배포 형태 자체가 다른 것**: 크롬 익스텐션형 실시간 단일 페이지
  진단(CMS 편집 화면에 바로 삽입) — 우리는 사이트맵 전체 크롤 기반
  대시보드. 별도 프로덕트 라인에 가까움.
