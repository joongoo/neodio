# Gemini API 수집

프롬프트 라이브러리에서 수집을 시작하면 기존 수집 요청에 Gemini 항목을 등록하고, 서버 큐에 연결한 뒤 요청 상세 링크를 표시한다. 이후 대기·수집·완료·실패와 원문은 수집 로그에서 확인한다. 화면을 닫아도 서버 작업은 계속된다.

- 모델: `GEMINI_MODEL` 환경변수, 미설정 시 `gemini-3.5-flash-lite`.
- 인증: 서버의 `GEMINI_API_KEY`를 사용한다.
- 동시 실행: 같은 DB를 사용하는 요청 전체에서 최대 3건. 시작 작업은 분당 최대 30건이며, 재시도 API 호출은 별도로 발생할 수 있다. Google의 프로젝트별 실제 할당량을 대신하지 않는다.
- 기존 검색 활성화·429 재시도·검색 없는 대체 답변 정책은 유지한다. 대체 답변은 인용률 계산에서 제외한다.
- 실행 전에 `gemini_collection_queue`에 항목을 저장하고 DB 잠금으로 선점한다. 큐 메시지가 중복 전달되어도 이미 시작한 항목을 자동 재전송하지 않는다.
- 저장된 결과는 작업별 고정 run ID로 복구한다. 결과가 없는 실행 중 작업은 3분 경과 후 실패로 남기며, 요청 로그에서 사용자가 재시도를 결정한다.
- 취소는 대기 작업에 적용한다. 이미 전송한 작업은 결과를 저장한다. 대기 항목의 ‘선택 대기 실행 요청’은 기존 큐를 깨우며 새 수집 요청을 생성하지 않는다.

## 실행 환경

Vercel에서는 `vercel.json`의 `gemini-collection` 큐 트리거가 `/api/queue/gemini`를 실행한다. 한 번에 최대 3건을 처리하고 남은 작업은 재전달로 이어간다. 배포 환경에서 기존 SERP API와 같은 Vercel Queues 연결 및 Gemini API 키가 필요하다. 배포·실제 과금 호출은 별도로 검증한다.

로컬 Next 서버는 응답 후 `after()`에서 같은 DB 큐를 처리한다. 브라우저와 독립적이지만 개발 서버가 종료되면 실행도 중단된다. 서버 재시작 후 요청 로그에서 대기 작업의 실행을 다시 요청할 수 있다. 과거 Gemini 기록은 자동으로 큐에 넣지 않는다.

스키마는 기존 DB 초기화·마이그레이션 경로에서 생성한다. 검사 명령은 `npm run test:gemini`이며, 유료 API 대신 mock과 롤백/폐기 가능한 DB fixture를 사용한다.
